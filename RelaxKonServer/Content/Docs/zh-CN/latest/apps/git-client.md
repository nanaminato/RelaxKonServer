# Git 客户端

Git 客户端（Git Client）面向 RelaxKonOS 服务端**文件系统中已经存在的 Git 仓库**。界面在客户端本地渲染，而仓库状态、提交历史与分支列表的真源都由服务端实时调用 `git` 采集。

## 概览

工作区状态、分支、历史与差异都是**当下的快照**，不做缓存也不建库。

**认证完全交给宿主**：`git` 调用以宿主操作系统进程身份执行，复用宿主用户与其权限；RelaxKonOS 不存储、不代理也不收集 Git 远程仓库的凭据。当推送或拉取需要凭据时，由宿主自身的凭据助手或 SSH 代理处理；凭据缺失时 `git` 返回失败，界面给出提示并引导在宿主上配置。

## 适用场景

- 服务器的某个目录就是一个 Git 工作树，需要直接在上面查看状态、提交与拉取。
- 需要在不给 RelaxKonOS 任何 Git 凭据的前提下操作仓库。
- 需要在服务端解决拉取产生的合并冲突。

## 当前能力

| 功能 | 说明 |
| --- | --- |
| 仓库选择 | 已注册仓库列表、当前选中仓库与切换 |
| 工作区状态 | 已暂存 / 未暂存 / 未跟踪 / 冲突文件清单，当前分支与上游领先落后计数 |
| 分支 | 本地与远程分支列表、切换、新建、删除 |
| 提交 | 勾选要暂存的文件、填写消息后提交 |
| 拉取 | 当前分支的合并或变基；未检出的分支只允许安全快进更新 |
| 推送 | 推送当前或指定本地分支到指定远程与分支，无需先切换 |
| 历史 | 提交列表与单次提交详情 |
| 差异 | 工作区、已暂存或某次提交的单文件差异 |
| 冲突解决 | 三栏比对、逐块选择、逐文件暂存，以及独立的继续 / 中止 |
| 反向提交 | 对指定提交生成反向提交 |

## 权限与安全

- 所有操作以**宿主 OS 进程身份**调用 `git`，越权由宿主直接拒绝，不另建访问控制层。
- 命令以结构化参数传递，不拼接 shell 字符串。
- 所有命令的工作目录固定为注册时记录的仓库路径；文件参数必须位于该仓库根目录之下，禁止越界。
- 危险操作需要二次确认：删除未合并分支、反向提交、覆盖未提交变更的切换、注销仓库注册。
- 注销仓库注册**只删除注册记录，不删除磁盘上的仓库目录**。
- 审计记录操作者、时间、仓库、动作与结果，不记录凭据。

## 平台差异

`git` 在 Windows 与 Linux 上的行为一致，平台差异只体现在可执行文件的探测与启动环境上，因此服务端是单一实现。

## 已知限制

当前为**第一阶段范围**，以下能力尚未提供，部分界面入口已占位但会明确说明不可用：

- 拣选提交、交互式变基与提交重排。
- 储藏、子模块深度管理、标签管理。
- 内置三方合并编辑器（冲突解决当前以逐块选择为主）。
- 多远程仓库的完整管理。
- 强制推送与硬重置：为安全起见不暴露。
- 二进制差异不返回补丁正文；过大的文本差异会被截断并标明。
