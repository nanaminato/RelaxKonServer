# 组件中心

组件中心（Component Center）是宿主组件的统一入口。它回答「这台服务器上的 Nginx、Docker、Git、FRP、代理核心和 Tailscale 是谁安装的、装了什么版本、来自哪个来源」，并在获得授权后执行安装、更新和保留数据卸载。

它不接管业务配置：站点、隧道、容器、订阅与共享目录仍由各自的应用管理。

## 组件与应用的边界

| 关注点 | 归属 |
| --- | --- |
| 组件程序本体、版本、来源、安装归属与生命周期 | 组件中心 |
| 服务启停、业务配置、日志与运行诊断 | 所属应用（Web 服务器、Docker、隧道、代理、文件服务等） |

应用侧只在「设置 → 组件依赖」中显示当前服务器的组件状态与跳转入口，**不再提供安装按钮**。这样同一台主机上不会出现两条互相不知情的安装通道。

## 页面

| 页面 | 内容 |
| --- | --- |
| 全部组件 | 按宿主平台过滤后的完整目录，含分类、接入方式与安装来源 |
| 已安装 | 宿主已确认存在的组件及其所有权 |
| 可更新 | 仅在拥有受管所有权且目录已确认存在更高版本时列出 |
| 工作负载 | 引用组件而非独立软件包的应用环境（例如代理服务端基础环境） |
| 任务与恢复 | 批量草稿、冻结任务计划、执行进度与待恢复操作 |
| 发布源 | 每个组件在当前平台声明的安装来源及其接入状态 |

目录只列出**当前宿主平台声明支持**的组件：Windows 宿主不显示 sing-box、Squid、Samba 与 Docker Engine。筛选、搜索、已安装与可更新共用同一判据，不按组件名写特例。

## 组件目录

| 组件 | 分类 | 支持平台 | 已接入的安装来源 |
| --- | --- | --- | --- |
| sing-box | 网络服务 | Linux | 系统包管理器（APT） |
| mihomo | 网络服务 | Linux、Windows | 系统包管理器（Linux）、可信归档（Windows） |
| frpc / frps | 网络服务 | Linux、Windows | 可信归档（两个方向分别报告） |
| Nginx | 网站与反向代理 | Linux、Windows | 系统包管理器（Linux）、可信归档（Windows） |
| Squid | 网站与反向代理 | Linux | 系统包管理器 |
| Docker Engine | 系统基础 | Linux | 系统包管理器；官方源尚未接入 |
| Git | 系统基础 | Linux、Windows | 系统包管理器（Linux）；Windows 只观测已有的 Git |
| Samba | 文件共享 | Linux | 系统包管理器 |
| Tailscale | 网络服务 | Linux、Windows | 系统包管理器（官方签名仓库）、官方系统安装程序（Windows MSI） |

「声明支持」与「已接入」是两件事：官方安装源在目录中可能标为「计划中」，提示存在但本版本没有事务实现，此时界面不会给出安装按钮。

## 安装归属

| 状态 | 含义 | 可执行的动作 |
| --- | --- | --- |
| 受管 | 由 RelaxKonOS 安装，并通过持久台账登记 | 更新、修复、回退、保留数据卸载（按组件与平台能力） |
| 外部安装 | 宿主上已存在，但未经 RelaxKonOS 安装 | 只读观察；不自动接管 |
| 待接入 | 目录已收录，安装仍由所属应用完成 | 仅跳转说明 |
| 未知 | 读取失败、权限不足或证据不完整 | 既不当作未安装，也不提供安装 |

外部系统包在 Linux 上可以**显式纳入管理**，前提是身份核验同时成立：dpkg 状态、程序文件归属、`dpkg --verify`（只允许配置文件变化）、服务归属与 `dpkg --audit` 全部通过。任一环节失败时保持「未知」，绝不降级为「未安装」。纳入管理只登记生命周期授权，**不重新安装、不接管业务配置、不改变服务启停**。

已被纳入管理的包若被外部 apt 升级，组件中心保留首次授权并提示「已核实的外部变更」，但不会把新版本当作原安装操作的成功回执。

## 变更流程

1. **读取状态**：`GET /api/v1.0/components/{componentId}/state`，取得所有权、实测版本、安装模式、宿主平台、问题码与待处理操作。
2. **冻结计划**：`POST /api/v1.0/components/{componentId}/plan`，固定来源、版本（或归档 releaseId）、每个工件的 URI、大小与 SHA-256，以及数据保留选择。
3. **确认并提权**：确认框列出宿主、动作、版本、来源、摘要与关联工件，随后按计划做一次宿主管理员授权。
4. **执行**：计划原样提交给该组件的安装台账，沿用同一幂等键、权限与持久操作记录。
5. **观察与恢复**：在「任务与恢复」中查看进度、请求取消或核对原操作。

约束是这个流程的重点：

- 执行**只使用冻结计划**；宿主状态修订、安装身份或目标版本变化都会作废计划，必须重新规划。
- 已进入安装阶段的系统包**不能以杀死包管理器的方式取消**。
- 失败与中断**不回退包版本**，也不把「当前服务健康」当作原操作成功；这类记录会留在工作区，等待核对。
- 卸载默认保留业务数据与配置；需要删除数据时是单独选择并单独确认的动作。

## 安装包来源

Windows 归档与文件安装提供四种来源，最终都交给同一安装台账：

| 来源 | 说明 |
| --- | --- |
| 由服务器下载 | 由服务器访问已批准的发布源并核对摘要 |
| 由本机下载后上传 | 客户端上传，引用与当前操作者绑定并会过期 |
| 从本机文件安装 | 选择本机归档并填写该文件的实际版本 |
| 从服务器文件安装 | 在服务器上选择已有归档，建立文件引用 |

「我要自己下载」只打开所选版本的官方发布页面；取得文件后仍需按上面的来源选择路径提交，不会因为打开过官方页面就放宽校验。

## 可信来源

- **系统包**：使用宿主已授权的软件源与签名元数据，冻结候选以及每个依赖工件的文件名、URI、字节数与 SHA-256。组件中心**不会自动添加仓库或签名密钥**；宿主未登记来源时返回明确的策略问题码。
- **可信归档**：使用配置中固定的版本列表，或官方 releases 目录（Nginx、Mihomo、frpc/frps、Tailscale），结果缓存 15 分钟，可手动刷新。官方反向代理与手动下载都受同一来源规则约束。
- **Tailscale（Linux）**：需显式确认 Tailscale Inc. 官方稳定版签名仓库及其密钥指纹，且不覆盖宿主上已有的不同来源或密钥。
- **Tailscale（Windows）**：固定官方 stable 元数据与 SHA-256，校验 WinTrust 发布者、MSI 产品/升级代码与架构后才进入安装事务。

固定版本只表示「配置中可用的版本」，不代表上游实时最新版；版本目录与「已是最新」都不作为安全结论。

## 版本检查与更新

选择组件时会自动读取宿主状态并准备版本信息，页面显示已装版本与来源提供的可用版本，仍可手动重新检查。

「可更新」需要同时成立：安装所有权已核实为受管、来源确认存在更高版本、宿主状态没有待恢复事务。仓库无更新、状态未知或事务未完成时，界面不会声称可以更新。

Linux 的系统包更新只接受比当前更高的版本，同版本不视为更新；更新与卸载面向 frpc/frps 的整个包，更新后需按业务入口重新启动隧道。卸载不需要选择归档目标。

## 启动门禁

应用在打开前会读取自己依赖的组件状态，结论分四类：

| 结论 | 处理 |
| --- | --- |
| 已安装 | 正常打开（服务停止也算已安装） |
| 未安装 | 提示前往组件中心，跳转不会自动安装 |
| 待恢复 / 执行中 | 先到「任务与恢复」处理，再打开应用 |
| 状态未知 / 无权限 | 不当作未安装，也不诱导入场安装 |

同一应用关联多个组件时，这些组件是**可替代**关系：隧道管理器的 frpc 与 frps 任一已安装即满足依赖。宿主声明该平台不提供某组件时归为「无需组件」并允许打开，避免把平台差异当成缺件。

## 权限与安全

- 读取需要 `server.components.read`，规划与提交需要 `server.components.manage`。
- 执行另需宿主管理员提权，按计划单独授权；不缓存、不复用上一次提权。
- 特权执行只接受闭集组件动词，不提供通用命令执行入口。
- 外部安装不会被自动接管；所有权结论只来自台账与核验证据，不来自「看起来像官方」。
- 包变更、控制与服务恢复共用同一原生锁，未决或损坏的包记录会阻止新的变更。

## 已知限制

- 接入程度按组件与平台分别推进：Windows Nginx 归档与 Windows Git 目前只有安装或观测中的一侧，多版本更新、修复与回退仍由所属应用或尚未接入。
- 系统包安装、外部更新、中断恢复与 `dpkg --verify` 的完整路径仍需在各平台实机验收；本文不把自动化检查当作宿主交付。
- 批量草稿与冻结任务计划只对已接入批量路径的组件开放（当前为 sing-box）；单个组件的安装入口仍以「任务与恢复」之外的面板为主。
- 移动端与桌面端共用同一套组件 API，但各自界面规则分别维护，不在两侧互相代替验收。
