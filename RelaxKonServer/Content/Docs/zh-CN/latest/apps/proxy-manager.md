# 代理管理器

代理管理器（Proxy Manager）在 RelaxKonOS 所管理的**当前主机**上安装、配置、启动、停止、监控和升级代理核心。

第一个正式支持的引擎是 **Mihomo**；功能围绕引擎抽象构建，因此后续可以增加其他无界面代理核心，而不是把模块写成某一个引擎的管理器。

## 概览

客户端**从不直连**代理核心的控制接口。所有调用先经过 RelaxKonOS 服务端，控制接口默认只监听本机；控制密钥只保存在服务端，不会返回客户端。

## 运行模式

| 模式 | 说明 |
| --- | --- |
| TUN | **一级模式**。以系统级方式接管流量，是服务器场景的主要形态 |
| 仅监听 | 只提供监听端口，由使用方自行指向代理 |
| 仅 RelaxKonOS | 限定作用范围，属于后续阶段 |

把 TUN 当成「高级可选开关」是本模块刻意避免的桌面 GUI 思路。

## 适用场景

- 服务器需要整机出网代理，而不是只给某个程序设置环境变量。
- 需要在代理不可用时仍能保住管理连接，避免把自己关在门外。
- 需要把订阅、配置与运行时版本纳入统一管理并保留回退路径。

## 当前能力

- 运行时管理：安装、升级、回滚、卸载与完整性校验；支持受管运行时与外部运行时两种形态。
- 配置与档案：原始配置与受管覆盖层分离，避免把复杂配置强行结构化。
- 订阅：更新前先校验与备份，失败回滚，不回显原始订阅地址。
- 代理组与节点：查看分组、切换选中节点。
- 连接：查看活动连接并支持关闭。
- DNS：作为独立状态展示，而不是藏在配置文本里。
- 实时日志：复用统一的流式通道，不另建一套推送机制。
- 管理流量保护：启用 TUN 前捕获管理路由快照，验证管理连接在改路由后仍然可达。
- 恢复机制：改变网络前写入恢复标记；启动时检测到未完成的启用动作会进入恢复评估，而不是直接忽略。
- 紧急禁用：单独提供「禁用 TUN 并恢复网络」的动作，它不等价于卸载引擎，配置档案会被保留。

## 权限与安全

- **两层权限同时成立**才允许操作：RelaxKonOS 自身的授权，以及宿主操作系统的提权。即使引擎以高权限身份运行，也不代表任意 RelaxKonOS 用户可以控制它。
- 特权助手只接受**固定的、强类型**的特权动作，不提供通用命令执行入口。
- 日常启停不应反复触发提权：安装与授权在首次完成，之后的开关不再需要用户审批。
- 危险动作（管理 TUN、管理运行时、执行恢复）必须经过服务端授权。
- 订阅地址、认证头、控制密钥、代理口令与私钥一律不进入普通日志，统一经过脱敏。
- RelaxKonOS 不会为了代理核心去关闭系统防护或添加全局排除项；被操作系统拦截时只显示诊断信息。

## 平台差异

| 平台 | 运行时托管方式 | TUN | 自动重定向 |
| --- | --- | --- | --- |
| Windows | 由长期运行的高权限助手托管进程，不再注册独立的代理服务 | 支持 | 不支持 |
| Linux | 独立系统服务 | 支持 | 支持 |

界面只根据服务端上报的平台能力显示选项，不在客户端自行判断操作系统。

## 已知限制

- 「仅 RelaxKonOS」模式属于后续阶段，当前以 TUN 与仅监听为主。
- 配置以「原始配置 + 受管覆盖层」管理，第一版不提供全部配置项的图形化编辑。
- TUN 相关的一批场景测试在无相应宿主环境时被跳过，跳过不计通过；平台证据需在目标主机上补齐。
- Windows 上启用 TUN 需要高权限助手就位，这不是一个普通开关，缺少它时界面会明确说明原因。
