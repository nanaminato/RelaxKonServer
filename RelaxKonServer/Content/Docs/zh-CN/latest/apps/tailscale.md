# Tailscale 管理器

Tailscale 管理器管理的是**服务器上的** Tailscale 节点，而不是客户端所在机器的 VPN。客户端不直连 `tailscaled`：状态读取、连接控制和配置变更都经服务端与特权 Helper 完成，返回的也只有结构化结果。

## 页面

| 页面 | 用途 |
| --- | --- |
| 设备 | 当前节点的连接状态、地址与组网设备列表 |
| 连接与配置 | 连接、断开，以及接收 DNS 与通告子网路由两个开关 |
| 首次登录 | 在服务器上发起官方登录，并把认证页交接到当前设备浏览器 |
| 操作记录 | 按宿主与账户保存的操作 ID，读取原始回执、核对与关账 |

## 设备

设备页只做观察：读取宿主 CLI 的 `status --json`，展示设备名称、DNS 名称、地址与在线状态。

组网设备列表需要**宿主网络授权**（资源 `host/tailscale`）。没有授权时仍显示本机状态，但会隐藏设备列表并说明原因，而不是返回一份看起来完整的空列表。

切换界面语言只重绘已取得的状态，不会重新查询宿主。

## 连接与配置

变更只有三个动作：连接、断开、变更配置。配置模型刻意做窄——只有「接收 DNS」与「接收路由」两个开关，不接受原生参数、登录密钥或自定义控制端。

一次变更分三步：

1. 读取当前宿主连接状态与配置；未读取时动作不可用。
2. 预览：列出宿主、动作、DNS 与路由的前后值。
3. 明确确认后执行。

确认框会直接说明风险：**此变更可能中断远程访问、DNS 或路由，包括当前这条会话；没有自动回滚。** 连接要求节点已经登录；本应用不会代替你完成登录。

执行经统一宿主提权入口，只在服务端明确要求时发起一次授权后重试。操作以 `operationId`、操作者、动作、预期修订与配置共同判定重复提交：同一个 ID 的不同内容会被拒绝，重复提交只返回原回执。

## 首次登录

首次登录页只在用户点击「发起登录」后准备计划，并在成功、明确确认与本地耐久保存操作引用之后才执行。

- 认证页**只在点击「打开官方登录页」时**交接到当前设备的系统浏览器；不会自动打开，也不会复制到剪贴板、写入磁盘或进入操作记录。
- 浏览器交接只表示「已请求打开」，不代表用户完成认证，也不代表 daemon 已登录。
- 登录挑战绑定原宿主、账户与**原登录会话**：重新登录产生的新会话不能领取旧挑战，同一账户可以读取原操作并核对关账。
- 关闭窗口只停止等待，**不会撤销已经签发的认证挑战**。

登录结果分为「已签发」「原生命令已完成」「需要设备授权」「未知」几种状态。需要设备授权时，应在管理后台批准设备，再回到此处刷新状态并核对原操作。

## 操作记录与恢复

操作引用保存在当前系统用户的本机目录下，按宿主与账户隔离，只记录身份引用，不含认证链接、配置或结果。

- 响应丢失时**不重放执行**：重新打开只读取服务端保存的原操作回执，界面保持「待核验」并暂时禁用变更。
- 存在未解决的操作时，新的连接、断开、配置与登录都会被阻止，并提示先读取原始回执。
- 结果未知时进入「核对恢复状态」：连续两次读取一致后，可以在新鲜授权与明确确认下**关账**。

关账的含义需要看清楚：它接受宿主**实测的当前状态**，解除该操作造成的变更阻断，**不重试、不回滚、也不把原操作改写为成功**。原结果仍然是未知，这个事实不会被后来的健康状态覆盖。

## 安装与卸载

安装不由本应用执行，统一在[组件中心](/docs/zh-CN/latest/apps/component-center)完成：

| 平台 | 来源 | 说明 |
| --- | --- | --- |
| Linux | 官方签名 APT 仓库 | 固定包名 `tailscale`、CLI `/usr/bin/tailscale`、服务 `tailscaled.service` |
| Windows | 官方签名 MSI | 冻结 `installer` 元数据，MSI 不作为归档解压 |

Linux 首次使用官方仓库时需显式确认来源及其密钥指纹；组件中心不会覆盖宿主上已有的不同来源。Windows 侧会在特权 Helper 内独立解析官方发行身份、核对摘要、WinTrust 发布者与 MSI 产品属性，再通过 Windows Installer 执行。

卸载保留登录与配置数据；安装或更新可能重启服务并中断当前远程连接。

宿主上已有的外部 Tailscale **不会被自动接管**：组件中心只报告「外部安装」，只有自有台账与核验证据同时成立时才认为具备管理权。

## 权限与安全

- 读取状态需要已认证会话；控制、登录与恢复另需宿主网络资源授权与管理员提权。
- 特权 Helper 只接受固定动词，拒绝路径、任意参数与修订以外的领域字段，不提供通用命令执行。
- 单条命令有执行时限与输出上限，超时、超限与畸形输出都按失败处理，不跨 IPC 返回原始 JSON 或底层诊断。
- 认证链接只在点击时通过专用短期通道交付，不进入状态、日志、回执或长期缓存。

## 平台差异与已知限制

| 平台 | 现状 |
| --- | --- |
| Linux | 已完成观察、控制与首次登录的实机验证（Ubuntu 26.04，Tailscale 1.104.4） |
| Windows | MSI 安装、跨版本变更、驱动与系统重启恢复仍需独立宿主验收 |

- 不声明受支持版本范围：版本兼容性以实机验收为准，不以文档推断。
- 界面只暴露「接收 DNS」与「接收路由」两个配置项；退出登录、认证密钥、强制重新认证、出口节点与子网路由发布都不在此应用的范围内。
- 移动端是同一套 API 的**控制端**，不在手机上运行 VPN 运行时；其界面规则与设备验收要求单独维护。
- 已知 CLI 位置的探测只覆盖 `/usr/bin/tailscale` 与 `Program Files/Tailscale`；其他安装布局暂不在本切片范围内。
