# Docker 管理器

Docker 管理器（RemoteDocker）在桌面里管理**服务端宿主机**的 Docker Engine。

它只管理**本机单一 Engine**：客户端不直连 Docker 套接字、不保存 Docker 凭据，守护进程接口也不会暴露到网络。

## 功能

- 引擎状态检测与安装引导
- 容器：查看、启动、停止、重启
- 镜像：列表与拉取
- Stack：Compose 校验、部署与停止
- 网络与卷：查看与管理
- 网络代理：守护进程层与构建层的出网代理
- 镜像源：按用户配置的 Docker Hub 兼容镜像源

## 实现方式

服务端通过 `IDockerEngineService` 调用 `docker` CLI，通过 `IDockerComposeService` 处理 Compose 编排，端点位于 `/api/v1.0/docker/*`。

## 镜像源

镜像源在 **Docker 管理器的「镜像源」页面**按 RelaxKonOS 账户配置，**不会写入宿主机的全局 `daemon.json`**。

- 可以维护多个 HTTPS、Docker Hub 兼容的 registry 主机，并选择其中一个或「默认」。
- 默认状态原样执行拉取，由 Docker 使用其默认仓库。
- 选中镜像源时，服务端把 Docker Hub 引用转换为对应该镜像源的地址后再调用 Docker CLI。
- 已显式写明仓库的镜像（例如带组织前缀的第三方镜像）不做转换，避免被错误发送到 Docker Hub 镜像源。
- 选择保存在服务端并**按用户区分**，因此一位用户的选择不会替换另一位用户的镜像源。

## 网络代理

在只能经代理出网的环境中，Docker 需要**两处相互独立**的代理配置，它们使用完全不同的宿主机制，因此状态按层分别报告，而不是合并成一个「代理已启用」的开关：

| 层 | 作用 |
| --- | --- |
| 守护进程层 | 守护进程自身的出网，例如拉取镜像 |
| 构建层 | 构建过程中的出网 |

- 代理来源可以是手动填写的地址，也可以复用内置代理运行时的监听端口；复用时会先做连通性探测，不可达则判定失败，不会把守护进程指向无人监听的端口。
- 构建层的代理值通过子进程环境变量传入，**不出现在命令行上**，因此本机其他用户无法从进程列表读到带凭据的地址。
- 代理地址可能内嵌用户名与口令。保存时加密存储；面向操作者的界面会原样返回该值（否则回填再保存会把真实凭据改写成掩码），而日志、审计与诊断信息一律去敏。
- 守护进程层是**宿主机全局**设置：Docker 守护进程属于机器而非某个工作区，因此它以最后一位获授权写入者的选择为准。
- 启用或移除守护进程层代理会重启 Docker 并中断运行中的容器，因此提交前会要求确认。
- 修改代理设置也可以直接在[设置](/docs/zh-CN/latest/apps/settings)的「网络」分类完成，两处是同一份配置。

## 引擎生命周期

启动、停止与重启整机 Docker 引擎是**宿主级操作**，它会中断本机全部容器，因此与单个容器的操作分开，且停止与重启必须显式确认。

这些动作只改变当前运行状态，不会启用或禁用开机自启，也不会改动宿主上的其他配置文件。

## 权限与安全

- 操作以服务进程在宿主 OS 上的身份执行
- 需要 Docker 权限的宿主（例如 `docker` 组或 root）才能完成变更类操作
- **Docker 访问默认关闭**：守护进程套接字的控制权接近 root 权限，因此部署时不会自动把服务账户加入相应权限组，需要在安装时显式选择（见[安装](/docs/zh-CN/latest/getting-started/installation)）
- 不引入独立的凭据存储；引用镜像仓库凭据时只保存引用
- 删除、强制停止、特权容器与 Docker 套接字挂载等操作必须二次确认

## 平台差异

| 平台 | 说明 |
| --- | --- |
| Ubuntu | 通过本机 Unix 套接字管理，守护进程层代理写入 systemd drop-in 后需要重启服务 |
| Windows 10/11 | 通过本机命名管道管理。若 Docker 不可用，状态按钮会打开内置引导：检查虚拟化、安装并启动 Docker Desktop、选择相应后端、确认 Linux 容器模式 |
| Windows Server | 只管理已安装且经能力探测合格的运行时，**不自动安装** |

Windows 桌面版路径适用于开发、个人自托管与验证；无人值守或生产部署优先使用独立 Linux 主机。

## 已知限制

- 只管理本机单一 Engine，不实现容器编排集群、多节点代理或远程守护进程接口。
- 安装、Stack 历史持久化、容器终端与流式资源统计仍处于设计阶段，界面不会宣称已经可用。
- 本应用设计为**由管理员使用的单实例工具**：当前授权以已登录用户为边界，没有为多人共享部署提供服务端的 Docker 读写角色隔离，因此不要把它作为多租户容器控制面暴露，也不要向不受信任的用户分发其登录凭据。
