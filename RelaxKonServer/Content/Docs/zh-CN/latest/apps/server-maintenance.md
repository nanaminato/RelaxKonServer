# 更新、卸载与维护

本教程用于已安装的 Server。远程主机从已信任的 SSH 连接进入服务器中心；Windows 10/11 本机从[管理本机](/docs/zh-CN/latest/getting-started/windows)进入。先阅读原安装状态，再选操作，不使用重新安装代替故障诊断。

## 1. 核对安装并安排维护

1. 选中正确的主机，刷新预检与安装状态，确认安装标识、模式、当前版本、程序/数据目录、端口和健康状态。
2. 告知正在使用 Server 的人；更新、修复或回退可能重启服务，客户端会断开。保留一条可恢复的 SSH 或本机管理通道。
3. 备份重要文件、配置和数据库，并确认备份可读取。版本回退只恢复程序，不承诺回退数据或数据库结构。
4. 查明是否有未完成操作；先读取其回执，避免重复部署。一个安装一次只执行一个维护动作。

| 永久清除受管数据 | 卸载并删除数据 | 不可用版本回退撤销 |

## 2. 更新服务端

1. 在已安装主机上打开安装／更新向导，确认它显示既有安装，不走首次安装。
2. 按[远程安装](/docs/zh-CN/latest/getting-started/remote-installation)选择官方、本地 ZIP、服务器 ZIP 或自定义 HTTPS 来源。核对模式、架构、目标版本和摘要。
3. 审阅既有安装标识和目录；更新沿用原安装的目录与配置。普通更新保留 TLS 身份，不隐式生成新证书。
4. 确认维护并观察传输、执行与核验阶段。服务重启期间连接中断不等于操作失败。
5. 重新连接或刷新同一主机，核对成功回执、目标版本和健康状态，再测试登录、文件浏览和终端。客户端需要新功能时另行更新客户端。

## 3. 修复与证书维护

选中已安装主机并执行“修复当前安装”，先核对原目录和安装身份。普通修复保留数据与现有 TLS 证书；只有明确选择重新生成 LAN 自签证书或提供新证书时才改变 TLS 身份。证书更新会重启服务，需要客户端重新核对并信任新证书，证书名称必须包含实际 LAN IP 或 DNS 名称。

Windows 个人模式的维护按需通过 UAC 配置独立助手；仅刷新状态不请求 UAC。Linux 系统模式修复仍需要 root 或可用 sudo。选择额外防火墙规则前确认目标端口与范围；不要把网络不可达直接归因于损坏安装。

## 4. 回退到前一程序版本

刷新状态，确认安装记录中存在前一版本，才使用“恢复前一版本”。没有前一版本时入口不可用。核对目标版本，完成备份与维护确认后执行；结束后刷新回执、版本和健康状态，重新登录检查常用功能。

回退沿用记录的目录并使用目标版本配套的部署引擎。它不是数据库、配置、文件或容器卷的历史恢复；新版已写入的数据能否由旧程序读取需要单独确认。

## 5. 卸载与数据保留

1. 再次核对主机和安装标识。先退出客户端会话，并备份需要保存的数据。
2. 选择“卸载服务端”。默认保留数据；若只是重装或暂时移除服务，保留此选项。
3. 只有确实需要永久清除时才选择删除受管数据，并按界面要求再次确认服务器名称。受管数据库、配置、密钥和日志可能被移除。
4. 执行后读取最终回执，并刷新主机状态，确认已不再安装；断开连接本身不能证明卸载成功。
5. 保留数据卸载后记录原目录，重装时核对保留的身份和数据位置；不要手工删除状态文件来伪造卸载。Windows 个人模式卸载还会移除个人助手和对应防火墙规则。

## 6. 读取操作记录与失败日志

在服务器中心选择对应记录，查看操作 ID、动作、阶段、状态和问题码。桌面可使用“从宿主刷新所选操作”取得主机侧结果及部署日志；Android 通过记录的“查看详情”打开详细摘要。安装失败、连接中断或结果未知时先刷新原操作，不要因为本机没收到成功就再次提交。

| 问题 | 处理顺序 |
| --- | --- |
| 暂存空间不足或账号配额耗尽 | 查暂存分区和配额，按操作 ID 保留日志，再释放空间 |
| 权限助手不可用 | 核对安装状态与问题码，用修复流程恢复组件，不提高 Server 日常权限 |
| 卸载引擎缺失 | 确认安装的版本化部署文件是否完整，修复后重试，不仅删除程序目录 |
| TLS 错误或 LAN 无法访问 | 核对地址、证书名称、监听和防火墙，必要时明确进行证书修复 |
| 状态与回执不一致 | 保留操作 ID，刷新主机结果；健康检查未通过前不标为成功 |

分享日志或截图前遮盖账号、地址、密码、私钥、令牌、配对码和敏感目录。截图占位图仅指定应展示的内容，不代表这些界面已被实机验收。

## 日常维护顺序

先检查安装与健康状态，再查看失败操作；需要变更时安排维护、备份、审阅并只提交一次。完成后核对回执、版本和健康，再实际测试登录、[文件管理器](/docs/zh-CN/latest/apps/file-manager)、[终端](/docs/zh-CN/latest/apps/terminal)和需要的宿主管理能力。

## 独立组件服务与维护边界

Windows 的受管 Nginx、Mihomo、FRPC/FRPS 使用独立 SCM 服务；Linux 的受管 FRPC/FRPS 使用独立 systemd 服务，每个 FRPC 配置对应独立实例。停止或卸载 Server、Guardian、Helper 不会自动停止保留的组件。重启 Server 后从持久化记录恢复管理状态，而不是依赖内存中的 PID。外部运行时仍须明确授权，不会自动转为受管服务。

默认卸载保留组件运行、配置及所有权记录；按原数据位置重装后可重新管理。完整删除数据会先清理受管 SMB、Nginx、FRP、Mihomo；清理失败或所有权冲突时保留程序、Helper 和数据，先读取失败回执再处理。接入的系统 Nginx 及其他站点、共享文件受所有权边界保护。卸载界面现可分别选择移除 SMB、Nginx、FRP、Mihomo，默认全部保留。保留任一组件时保留整个数据根与管理记录；勾选完整删除数据会选择移除全部四项，取消任一组件的移除会取消数据删除。Docker Engine、容器及卷不属于这四项清理范围。

隔离 Windows/Linux 主机的服务生命周期、系统重启、保留数据卸载与重装已验证；GUI/API 全流程和跨版本升级仍需回归。详见[独立组件实现与验收](https://github.com/nanaminato/RelaxKonOS/blob/master/docs/services/RelaxKonOS.IndependentComponentServices.Progress.md)与[更新、卸载与维护](/docs/zh-CN/latest/apps/server-maintenance)。
