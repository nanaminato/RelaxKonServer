# 应用部署

应用部署（Application Deployments）是一个**与 Docker 管理器分离**的内置应用：Docker 管理器负责操作引擎与容器原语，应用部署负责把一份「应用」当成长期存在的实体来发布、观察和回退。

## 概览

部署对象由**期望状态**（要跑哪个修订、用哪份配置、暴露哪个端口）与**实际状态**（引擎里真实存在的容器和就绪结果）两部分组成。当两者不一致时，界面显示为「漂移」，并说明差异来自缺失、外来修改还是未受管资源。

## 适用场景

- 把团队构建好的镜像或发布包交付到一台长期在线的宿主上运行，而不必手工登录服务器敲命令。
- 需要保留历史修订，并在新版本就绪检查失败时退回上一版。
- 需要查看部署过程与容器实时日志，且不希望把宿主的 Docker 凭据交给客户端。

## 支持的来源

| 来源 | 说明 |
| --- | --- |
| 容器镜像 | 指定镜像引用与标签，服务端固定镜像身份后创建容器 |
| Java | 上传 JAR 发布包，按模板校验入口与参数 |
| .NET | 上传 Web / Worker 发布包，可选择自包含发布 |
| Python | 上传带锁定依赖的项目，构建在镜像内完成 |

模板会声明自身是否需要归档、是否需要镜像引用、是否支持自包含以及默认容器端口，因此入口与参数的校验发生在部署之前。

## 当前能力

- 多步部署向导：来源、产物、入口、端口、资源与代理路由在同一流程内确认。
- 修订与操作记录：每次发布生成不可变修订，操作记录可追溯。
- 就绪检查：HTTP 与进程两级判定；候选未就绪不会接管流量。
- 版本回滚：复用已发布的修订，不重新构建。
- 实时日志：以流式方式推送部署日志。
- 上传进度：显示已传输字节、百分比与速率，并支持取消。
- 镜像版本选择：从镜像仓库读取可用标签供选择。
- 可选代理路由：为应用增加一条根路径路由，保存前先校验站点配置。

## 权限与安全

- 读取与变更分别由独立策略控制；变更类请求需要宿主能力已启用。
- 长操作携带幂等键，重试不会产生第二次副作用。
- 同一应用的变更互斥，不同应用可以并行。
- 审计只记录操作者、目标、结果与操作编号，不记录凭据。
- 密钥以服务端数据保护机制加密保存，接口只上报版本号。
- 上传内容按条目数、展开总量与路径边界校验，并拒绝越界路径与符号链接。

## 平台差异

应用部署的目标是**运行 Docker Engine 的宿主**，因此主要用于 Linux 服务器；Windows 侧适合作为客户端与开发环境。

## 已知限制

> **当前状态：已实现待验证。** 全部实现项已完成编译与静态校验，但运行期行为尚未在真实 Docker Engine 上验收，因此不应把本页理解为「已具备生产能力」。

- **真实引擎验收未完成**：镜像拉取、构建、创建、就绪、回滚与故障注入等场景尚未在具备 Docker 的宿主上执行。
- **单服务 Compose 项目部署未实现**：当前改用容器原语表达部署，因此不能在向导中直接提交一份 Compose 项目。
- **不承诺总体百分比**：构建阶段按阶段内工作量上报进度，没有可靠分母时进度显示为未知，而不是编造数值。
- 不代替持续集成系统：没有源码构建、仓库钩子或流水线定义。
