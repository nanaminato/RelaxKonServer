# 证书管理器

证书管理器是**本机证书生命周期管理器**。RelaxKonOS 自己就是 ACME 客户端，不采用控制器 / 代理、多机调度或跨机私钥分发那类架构。

## 概览

三条原则决定了整体形态：

1. **私钥始终在本机生成和保存**，不通过接口返回给客户端。
2. **签发与部署分离**：证书管理器不知道 Nginx、IIS 或反向代理的存在，部署由独立的部署器负责。
3. **不要求 RelaxKonOS 永久占用 80 端口**。

## 适用场景

- 服务器位于公网，希望由 RelaxKonOS 自己的 HTTPS 端点使用受信证书。
- 服务器上已有 Web Server 占用 80 端口，但希望在不抢占该端口的情况下完成验证。
- 需要自动续期，而不是每年手工更换证书。

## 当前能力

- ACME v2 签发流程，签发机构通过目录地址配置，不写死任何一家 CA。
- 验证方式：自动、HTTP-01（临时监听 / WebRoot）与 DNS-01。临时监听仅在 80 端口空闲时短暂使用，只路由挑战路径，签发完成、取消或超时后确定性释放。
- WebRoot 模式：写入挑战文件后回读校验，验证结束后清理。
- 证书存储：以 PEM 作为统一格式的文件存储，Windows 与 Linux 使用同一模型。
- 密钥算法：RSA 与 ECDSA。
- 部署目标：RelaxKonOS 自身的 HTTPS 端点（Kestrel）。
- 自动续期：优先采用 ACME 的续期信息（ARI）建议窗口，并以证书到期时间作为兜底。
- 管理界面：概览与证书列表；概览显示受管数量、刷新状态与申请入口，证书页按选中项提供部署、续期、吊销与删除。
- 申请对话框：域名、联系邮箱、验证类型、密钥算法与公网可达性确认集中在可滚动内容区内，预检结果与签发进度也显示在其中。

## 权限与安全

- 会改变宿主机状态的操作（申请、续期、删除、导入、部署、监听 80 端口、修改 HTTPS 绑定）只在 RelaxKonOS 以管理员身份运行时执行；权限不足时返回稳定问题码。
- 客户端只显示本地化说明，不收集或转发 sudo、UAC 与服务账户口令，也不把接口变成任意命令提权通道。
- **私钥、账户密钥、CSR 与完整 CA 响应不出现在接口、日志、审计或错误详情中**；正常接口只返回域名、签发机构、序列号、有效期、状态、指纹与续期状态。
- 预检返回结构化结果：域名规范化与重复 SAN 校验、A / AAAA 解析、80 端口的监听权限与占用、防火墙与上游代理情况。预检不会伪造「公网可达」的结论。
- 接口返回长操作编号与阶段，取消与断线不会丢失服务端状态。

## 平台差异

- 目标平台为 **Ubuntu 24.04 LTS** 与 **Windows Server 2016 及以上**。
- Linux 上私钥目录权限收紧到仅服务账户可读；Windows 使用文件系统 ACL 限制到服务账户与系统。
- 证书核心不依赖 Windows 证书存储，避免把一个平台存储变成全局依赖。

## 已知限制

- **待目标平台验收**：核心与基础管理界面已实现，但真实签发机构、监听行为与文件权限的验收仍需在目标主机上执行。
- **DNS-01、通配符证书**未实现，属于后续阶段；因此完全无法开放 80 端口的环境当前无法完成验证。
- **Nginx、IIS、Apache 的部署集成未实现**，当前部署目标只有 RelaxKonOS 自身的 HTTPS 端点。
- 80 端口空闲并不构成验证一定成功的保证；DNS、NAT、CDN 或上游反向代理状态无法确定时，界面会标记为需要管理员确认。
