# 配置注册表

配置注册表（Registry）是一个内置应用，用来浏览**服务器 schema 明确允许的配置型期望状态**及其同步状态。

**它不是宿主操作系统的注册表。** 它不提供宿主 Windows 注册表、任意数据库表、机密、会话或高风险命令的入口，路径由代码内的 schema 白名单控制。

## 概览

应用采用左侧键树、右侧值表和底部编辑器的布局。用户可以新建、修改和删除自己作用域内的逻辑注册表值，刷新会从服务端重新读取。

同步、版本与重启属于内部实现，不展示给用户。

## 适用场景

- 需要按用户查看工作区级别的配置项，而不是直接改文件。
- 需要一处明确的、受 schema 约束的配置入口，避免把任意配置文本暴露出来。

## 当前能力

- 按键浏览：Client 只请求当前打开的键的**直接子键与直接值**，不会在展开某个根键时拉取全量内容。
- 编辑：新建、修改、删除自己作用域内的值。
- 持久化：服务端内存注册表承载当前状态，修改以短暂的待同步状态批量写回数据库，正常关闭时再刷新一次。
- 默认项：工作区的终端外观、桌面偏好、浏览器设置与窗口布局均以各自键的默认值直接写入注册表；旧的配置文件不参与读取、迁移或回写。

## 权限与安全

- 读取以认证用户标识作为租户边界；未认证、未知作用域与其他用户的数据都不可访问。
- 只有工作区范围内的键可以由用户创建或删除；删除键会一并删除其子键与值。
- 键与值按相同的所有权边界隔离，两位用户的列表互不包含对方数据。
- 该应用不访问任何操作系统注册表。

## 平台差异

该应用与接口在 Windows 与 Ubuntu 上共享**同一套托管实现**，因此没有平台分支。

## 已知限制

- 不展示同步、版本与重启状态，它们属于内部实现。
- 尚未提供编辑历史、乐观并发与跨实例缓存失效，这些属于后续阶段。
- 不要把它当作通配的配置面板：不在 schema 白名单内的路径无法访问，也不会因为界面存在而被放开。
