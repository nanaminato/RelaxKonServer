# 远程安装：逐步操作

本教程从一台尚未安装 RelaxKonOS Server 的远程主机开始，使用桌面客户端的服务器中心完成安装。Android 入口和界面布局不同，但来源、模式、回执与健康检查的原则相同。Windows 10/11 本机安装请改用[管理本机教程](/docs/zh-CN/latest/getting-started/windows)，不需要 SSH。

## 1. 准备主机、客户端与凭据

1. 从[下载页](/downloads)取得适合本机架构的客户端。确认目标主机地址、SSH 端口、管理账号，以及可用的密码或私钥。
2. 确认目标主机已启用 SSH，客户端能够连接该端口；首次安装不要求主机已有 Server API。
3. 从主机控制台或可信管理员处取得 SSH 主机密钥指纹，连接时逐项核对。指纹变化时先确认重装、密钥轮换或地址变化的原因。
4. 检查目标架构、磁盘空间与配额、计划使用的服务端端口。远程安装默认为 5000；端口已有服务时另选一个。

| 目标模式 | 安装前条件 | 何时选择 |
| --- | --- | --- |
| Linux 系统模式 | 支持的 Linux、systemd、Python 3；root 或可用 sudo | 需要系统服务、多用户和明确授权的宿主管理能力 |
| Linux 用户模式 | 非 root 账号；Bash、Python 3、curl、unzip、realpath、stat、find、sha256sum、flock | 只为当前用户安装，不需要 sudo 或 systemd |
| Windows 系统模式 | 系统 PowerShell，已提升管理员权限的 SSH 会话 | 远程维护 Windows 10/11 或 Windows Server 的系统服务 |

Linux 系统模式默认支持 Debian 12 与 Ubuntu 22.04/24.04/26.04。其他系统需在高级设置明确允许，仍须通过依赖和权限检查。Windows 个人模式从目标电脑本机入口安装，不作为本教程的 SSH 模式。

## 2. 添加 SSH 主机并确认信任

1. 打开客户端的服务器中心／安装或管理服务器；桌面登录页也可选择 SSH 连接入口。
2. 填写目标地址、SSH 端口和账号，选择界面支持的密码或私钥认证；私钥有口令时一并填写。
3. 连接后比对主机密钥指纹，确认是目标主机后再选择信任并连接。不要用忽略校验来绕过指纹变化。
4. 保存连接资料时检查是否选择保存凭据；敏感凭据由本机安全存储管理，不随工作区同步。

## 3. 运行预检并选择安装模式

选中该主机并运行环境检查。阅读识别出的操作系统、架构、权限、依赖、安装状态和端口结果；检查不通过时先解决对应问题。Linux 系统模式可使用普通 SSH 账号加 sudo，sudo 密码留空时尝试当前 SSH 密码；Windows 系统模式的 SSH 会话必须已提升。Linux 用户模式不能使用 root。

若预检发现已有安装，先核对它的安装标识、模式与目录，再按[更新和维护教程](/docs/zh-CN/latest/apps/server-maintenance)操作，不把另一份安装当成首次安装覆盖。

## 4. 选择发布包来源

| 来源 | 你需要填写或选择 | 传输发生在哪里 |
| --- | --- | --- |
| 官方稳定版 | 选择官方来源，可选 HTTPS 发布目录 | 目标主机下载并核对官方 ZIP 摘要与逐文件清单 |
| 本地发布包 | 选择本机 ZIP | 客户端上传到目标主机，适合目标无法上网的情况 |
| 服务器上的发布包 | 选择或填写目标主机 ZIP 绝对路径 | 直接读取目标文件，不从客户端上传 |
| 自定义 HTTPS | ZIP 的 HTTPS URL 和完整 SHA-256 | 目标主机下载，按填写的摘要核验 |

Windows/Linux 系统模式选择 `*-server.zip`，Linux 用户模式选择 `*-user-server.zip`；`*-client.zip` 不能安装服务端。来源选择不会改变包类型和架构检查。本地与服务器 ZIP 仍检查必要文件、安全解压及安装清单结构。可下载版本以目录为准，不能从源码说明推断旧发布包已包含某功能。

## 5. 设置目录、网络、证书和权限

1. 设置程序、数据目录和服务端端口；自定义路径用目标主机上的绝对路径。Linux 用户模式还可指定 XDG 配置、状态与缓存目录，避免重叠。
2. 同一台目标主机访问可使用仅本机监听。跨设备访问选择 LAN，并配置能够覆盖实际 IP 或主机名的 HTTPS 证书；监听 LAN 不等于防火墙已放行。
3. 系统模式可选择无证书、自有 PFX/P12 或 PEM 证书链与私钥、自签名证书。填写证书密码时不会在审阅页显示明文。
4. 审阅文件范围，优先只授予实际需要的路径；Linux 管理员/root 的文件范围单独配置。Docker 授权默认关闭，需要时明确选择。
5. Linux 用户模式默认 loopback，可通过客户端管理的 SSH 隧道连接；详细限制见[用户模式](/docs/zh-CN/latest/getting-started/user-mode)。

## 6. 审阅、执行并核验

提交前再次确认主机、模式、包来源、目录和端口。一次只维护这份安装的一个操作；不要从另一个客户端重复提交。确认后依次观察传输、安装执行和结果核验。目标主机下载的总大小未知时，进度可能不显示百分比。

![截图占位 · 待替换：截图位置：最终审阅页；展示主机、安装模式、包来源、目录和端口摘要。](/assets/docs/screenshots/zh-CN/remote-review.svg)

下载或上传到 100% 只代表传输阶段结束。成功必须同时有主机侧成功回执、安装状态和独立健康检查。保存操作 ID；失败时查看阶段、问题码与日志，而不是根据窗口关闭或启动器退出码判断。

## 7. 连接安装好的 Server

返回 Server 登录入口，用所配置的可达地址连接并登录支持的系统账号或 Alias。仅本机监听和 Linux 用户模式可使用“通过 SSH 隧道连接”，Server 地址填写目标 SSH 主机上的回环地址和所选端口，例如 `http://127.0.0.1:5000`。HTTPS 名称和信任链仍需核验。SSH 精简桌面本身不等于 Server 工作区。

## 失败时先检查什么

| 现象 | 下一步 |
| --- | --- |
| SSH 连接失败或指纹变化 | 核对地址、SSH 端口、账号、主机密钥；确认主机身份后再重试 |
| sudo／管理员检查失败 | 核对当前会话是否满足目标模式权限，不通过提高 Server 日常运行权限绕过 |
| 包类型、架构或摘要失败 | 重新核对 ZIP 来源、RID、模式和摘要，不关闭官方校验 |
| 空间或配额不足 | 检查目标暂存分区及账号配额，腾出足够空间后重新预检 |
| 操作中断或结果未知 | 重连同一主机，刷新状态和原操作回执，查明结果后再提交新操作 |
| 安装成功但连接失败 | 核对监听地址、端口、防火墙、TLS 与客户端地址，不立即重装 |
