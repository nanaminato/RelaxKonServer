# Windows 10/11 の個人用 PC

Windows 10/11 では同じ PC で Server とデスクトップ Client を実行できます。本機管理は個人モードが既定で、システムモードも選べます。Windows Server はシステムモードのみ対応します。

本ページは現在のソースの対応内容を説明します。公開成果物は[ダウンロード](/downloads)と[リリースノート](/releases/0.1.2)で確認してください。過去のパッケージにこれらの機能が含まれるとは限りません。

## モードの選択

| モード | 実行ユーザーと動作期間 | インストールと保守 |
| --- | --- | --- |
| 個人 | インストールを開始した Windows アカウントが所有。Server は非昇格で実行し、サインイン時に起動、サインアウト時に停止。Client を閉じても Server は停止しません | SSH 不要の本機管理。導入・更新・修復・ロールバック・削除で UAC を使って独立した特権ヘルパーを設定 |
| システム | Server、Guardian、特権ヘルパーをシステムサービスとして実行。対話ログインがなくても動作し、システムサービスや複数ユーザー向け | 本機導入には管理者権限、リモート保守には昇格済み管理者の SSH セッションが必要 |

プログラム、データベース、インストール識別子、操作履歴は独立しており、自動変換しません。共存時は異なるポートを使います。Windows 10/11 のシステムモードは Windows Server と同じ認可規則を使い、一般ドメインユーザーを自動的に管理者としません。

## インストールと本機の認証

1. アーキテクチャに合う Windows デスクトップ Client と Server パッケージを用意します。ログイン画面の**本機を管理**から個人モードを選択します。OpenSSH Server や既存の Server ログインは不要です。
2. 公式リリース、ローカル ZIP、または SHA-256 付きカスタム HTTPS ダウンロードを選び、ポート、ネットワーク、TLS、特権ファイル範囲を確認します。個人モードは固定のユーザー別ディレクトリと `*-server.zip` を使います。
3. 導入時の UAC を承認します。別の管理者の資格情報で承認しても、所有者、データ、ログイン時の起動設定は開始ユーザーのままです。UAC のキャンセルやヘルパー導入の失敗では配置は失敗します。
4. 操作結果と独立した正常性確認を待ちます。同じ PC のループバックアドレスへ接続し、**この Windows 端末を設定**を選びます。Negotiate が現在の Windows アカウントを検証して端末公開鍵を登録するため、アカウントパスワードや Hello PIN は不要です。
5. 個人モードの本機認証は所有者だけが行えます。他の Windows 管理者は代替できません。以後は端末鍵の署名でログインします。鍵を紛失した場合、所有者は同じ本機認証入口から復旧できます。

Windows 10/11 システムモードでは本機管理者がループバック Negotiate で端末鍵を設定・復旧できます。Windows Server はこのワークステーション向け入口を提供しません。個人モードの所有権で別のシステムモード環境へアクセスすることはできません。

## 権限、データ、日常利用

所有者は Windows Administrators に加入せず、そのインストールの RelaxKonOS 管理者機能を利用できます。通常のファイル、ターミナル、Docker Desktop は所有者の環境と権限を使います。個人モードは Guardian システムサービスやユーザーをまたぐ Guardian を提供しません。各アプリの機能は実際のプラットフォーム検出に従います。

プログラムは `%LocalAppData%\RelaxKonOS-Personal\program`、永続データは同階層の `data`、操作結果と診断は `deployment` にあります。独立した LocalSystem ヘルパーは保護された `%ProgramFiles%\RelaxKonOS-Personal\<SID>` に配置し、ネットワークのヘルパー入口を提供しません。

通常権限で失敗したファイル操作はヘルパーを利用できますが、導入時の確認範囲に制限されます。既定は管理データだけで、許可一覧または全ローカルディスクを明示的に選べます。管理者ターミナルは LocalSystem で実行し、ユーザーのネットワークドライブやドメイン資格情報を継承しません。有効化すると所有者とペアリング端末に本機のシステムレベルのコマンド実行を許可します。日常の特権操作で UAC を繰り返し要求せず、Windows 管理者パスワードを保存しません。

## 他の端末のペアリング

1. 本機認証と端末鍵ログイン後、ペアリングコードを生成します。
2. コードは 10 分間有効で 1 回だけ使用できます。Server 再起動で未使用コードは失効します。
3. 新しいデスクトップまたは Android クライアントは独自の秘密鍵を生成し、コードで公開鍵を登録して署名チャレンジでログインします。秘密鍵は端末内に保持し、Server は公開鍵だけを保存します。所有者や管理者のパスワードは不要です。
4. 端末は同じ所有者アカウントとワークスペースを使い、新しい Windows ユーザーを作りません。所有者は端末を一覧表示・失効できます。失効で該当端末のアクセス・更新トークンと既存 Hub 接続が無効になり、他の端末やパスワードセッションには影響しません。

他の端末から接続するには LAN で待ち受け、到達可能なホスト名または IP を使います。ペアリング先に `127.0.0.1` や `localhost` は使えません。実際のアドレスをカバーする証明書で HTTPS を設定します。個人モードの導入・保守で明示的に追加できるファイアウォール規則は Domain/Private ネットワークの LocalSubnet に限定されます。他の範囲は Windows 管理者が設定し、LAN 接続はインターネット公開を意味しません。

## 更新、ロールバック、削除

本機管理から対象のインストールを保守します。更新・修復・ロールバック・削除は識別子を確認し、必要に応じて UAC を要求します。状態の更新は UAC 不要です。削除は既定でデータを保持し、個人ヘルパーと対応するファイアウォール規則を削除します。データの完全削除は別途確認します。

自動検査はアカウント分離、端末ペアリングと失効、デスクトップ配置要求、システムモードの認可回帰を確認しています。公開前には別の管理者による UAC 承認、LAN HTTPS と Android ペアリング、特権ファイルとターミナル、サインアウトと再ログイン、ロールバックと削除、両モードの共存を実機で確認してください。実装と検証範囲はソースの[個人用 PC ガイド](https://github.com/nanaminato/RelaxKonOS/blob/master/deployment/WindowsPersonalComputer.md)を参照してください。
