# インストール

RelaxKonOS はクライアントとサーバーで構成されます。端末にクライアントをインストールし、**サーバーセンター**からサーバーをインストールまたは管理します。

## インストール前の準備

- [ダウンロード](/downloads)から端末に合うクライアントを取得します。公開パッケージの使用には .NET SDK は不要です。モバイルは [Android](/docs/ja-JP/latest/getting-started/android) を参照してください。
- 対象ホストで SSH を有効にし、管理アカウントを準備します。接続時にホスト鍵の指紋を確認してください。
- Linux システムモードの既定の対応環境は Debian 12、Ubuntu 22.04/24.04/26.04 です。root または使用可能な sudo、systemd、Python 3 が必要です。それ以外の Linux は詳細設定で明示的に許可します。
- Linux ユーザーモードは非 root アカウントを使用します。Bash、Python 3、curl、unzip、realpath、stat、find、sha256sum、flock が必要で、sudo と systemd は不要です。
- Windows システムモードは昇格済み管理者の SSH セッションとシステム PowerShell が必要です。
- アーキテクチャ、空き容量、依存関係、ポートを確認します。初回インストールは Server API が存在する前にホストの SSH を使用します。

## クライアントからインストール

1. **サーバーセンター／サーバーのインストール・管理**を開きます。デスクトップではログイン画面から SSH に接続してサーバーセンターを開くこともできます。
2. SSH のアドレス、ポート、アカウントでホストを追加し、ホスト鍵を確認して信頼します。
3. 事前チェックを実行し、**サーバーをインストール**を選びます。インストール済みの場合は識別子を確認してアップグレードします。
4. 入手元、モード、設定を選び、対象ホストと構成を確認します。
5. 確認後、ホスト側の操作結果と正常性チェックを待ちます。失敗時は操作履歴の原因とログを確認します。
6. 完了後にログイン画面へ戻ります。ユーザーモードやローカル限定の構成にはクライアントが管理する SSH トンネルを使用できます。

## リリースの入手元

| 入手元 | 操作と検証 |
| --- | --- |
| 公式安定版 | ホストがダウンロードし、公式 ZIP の摘要とファイル一覧を検証します。HTTPS カタログのベース URL も設定できます |
| ローカルパッケージ | クライアントで ZIP を選択してアップロードします。オフラインのホストにも使用できます |
| サーバー上のパッケージ | サーバーの ZIP の絶対パスを入力または参照し、そのファイルを直接読みます |
| カスタム HTTPS ダウンロード | ZIP の HTTPS URL と 64 桁の 16 進数 SHA-256 を指定し、ダウンロード後に検証します |

ローカルとサーバー上のファイルも種類、アーキテクチャ、必要ファイル、安全な展開を確認します。システムモードは `*-server.zip`、ユーザーモードは `*-user-server.zip` を使用し、クライアントパッケージは代用できません。実際の公開状況はダウンロード一覧に従います。

## インストール設定

| 設定 | 適用範囲と説明 |
| --- | --- |
| モード | Linux システム、Linux ユーザー、Windows システム。自動選択は事前チェックに従います |
| サーバーポート | 1–65535、既定は 5000。使用可能なポートを指定します |
| プログラムとデータのディレクトリ | システムモードでは別々に設定できます。ユーザーモードはデータ配下にプログラムを保存します。空欄は既定、既存環境は記録済みのパスを使用します |
| 設定、状態、キャッシュのディレクトリ | Linux ユーザーモードは XDG に対応する 4 つのルートを設定できます。重ならない絶対パスを使用します |
| ネットワーク | システムモードはローカル限定または LAN、ユーザーモードのウィザードはローカル限定を既定とし、`listen-host` で LAN を設定できます。LAN の選択でファイアウォールは自動変更されません |
| TLS 証明書 | システムモードはなし、自分の証明書、自己署名から選択します。PFX/P12 とパスワード、または PEM チェーンと秘密鍵を指定します。自己署名の名前はカンマ区切りです |
| ファイルアクセス | システムモードは制限付き、許可一覧、全体から選択します。許可するホスト絶対ディレクトリを 1 行に 1 件入力します |
| 管理者と root のファイル範囲 | Linux システムモードでそれぞれ独立した範囲と許可一覧を設定します |
| Docker の許可 | Linux システムモードで明示的に許可します。既定は無効です。Docker ソケットの操作権限は root に近い権限です |
| 対応一覧外の Linux | 詳細設定で明示的に許可します。アーキテクチャ、権限、依存関係の確認は継続します |
| sudo の認証情報 | Linux システムモードは root または sudo パスワードを使用します。空欄では現在の SSH パスワードを試します |

言語、固定の操作、非対話実行、パッケージの一時配置、証明書パスワードファイル、既存のインストール識別子はクライアントが処理します。スクリプト引数の手入力は不要です。確認画面には証明書パスワードを表示しません。

## 更新、修復、アンインストール

サーバーセンターでインストール済みホストの管理操作を開きます。更新、修復、ロールバックは記録済みディレクトリを使用し、保持したデータへの再インストールは識別子を引き継ぎます。通常の更新と修復では TLS の識別情報を保持し、証明書の再生成は明示的な選択です。

アンインストールは既定でデータを保持します。データベース、設定、鍵、ログの完全削除は別途確認が必要です。操作後にクライアントがホストの状態を確認します。特権ヘルパーが使用できない場合は操作ログを確認して修復してください。

## 初回ログイン

正常性の確認後、ホストのシステムアカウントまたは設定済み Alias でログインします。システムアカウントはホスト認証、Alias は独立したパスワードハッシュを使用します。サーバーはシステムログインのパスワードを永続保存せず、保存は端末の安全な保存領域での明示的な選択です。
