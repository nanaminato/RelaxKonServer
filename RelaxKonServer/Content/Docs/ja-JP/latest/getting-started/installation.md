# インストール

> このページは現在のソース機能を説明し、特定パッケージの収録機能一覧ではありません。公開成果物と日付は[リリースノート](/releases/0.1.2)、検証状況はリンク先の実装記録で確認してください。

RelaxKonOS は**クライアント**と**サーバー**で構成されます。クライアントは毎日使うデバイスに、サーバーはワークスペースを常時保持したいマシンに配置します。

## 前提条件

- **.NET 10.0 SDK** 以降
- クライアント OS：Windows 10/11、macOS、Ubuntu 20.04+
- サーバー OS：Ubuntu 20.04+ または Windows Server 2016+

## まずサーバーのインストール方法を選ぶ

| 方式 | 権限 | 説明 |
| --- | --- | --- |
| [ユーザーモード](/docs/ja-JP/latest/getting-started/user-mode) | sudo 不要 | 一般の Linux アカウントでサーバーを実行。`127.0.0.1` のみ待ち受け、システムディレクトリは変更しません |
| システムモード | root / 管理者 | ワンコマンド インストーラーがシステムサービスと特権ヘルパーを登録。マルチユーザー本番環境向け |
| ソースから実行 | .NET 10 SDK | 以下に示す手順。開発とデバッグ向けです |

> **Note**: 以下の手順は .NET SDK を必要とし、ソースツリーを直接実行するもので、**一般ユーザー向けのインストール方法ではありません**。サーバーを配備する場合は、先に[ユーザーモードでのインストール](/docs/ja-JP/latest/getting-started/user-mode)または公式サイトの[ダウンロードページ](https://relaxkon.com/downloads)をお読みください。

## ホストの認可と特権ヘルパー

サーバーは **root や管理者として動作しません**。ホストの特権を必要とする操作はすべて専用の特権ヘルパーを通り、ヘルパーは固定の構造化された操作のみを受け付け、汎用のコマンド実行入口を提供しません。以下は導入後にどの機能が使えるかを左右します。

### 管理者権限が前提

システムモードで導入すると、専用のサービスアカウントが作成され、ヘルパーの公開ディレクトリとポリシーファイルはそのアカウントから書き込み不可となり、サービスアカウントだけが引数なしでヘルパーを呼び出せます。その結果：

- **検出と読み取り専用の機能**は、サービスプロセスが読める限り利用できます。
- **ホストの状態を変える機能**（ランタイムの導入、システム設定の書き込み、システムサービスの制御、証明書の配置など）は RelaxKonOS が十分な権限を持つことを必要とします。不足時は画面が明示的な問題コードを返し、より高い権限での再導入を求めます。黙って失敗することはありません。
- ホスト認可は統一管理者認証を使用します。システム認証済み管理者は資格を動的に確認し、一般ユーザーと Alias は選択した管理者を明示的に認証します。資格情報をログや任意 shell コマンドに入れません。導入権限と日常操作の認可は別で、[ログインとアカウント安全](/docs/ja-JP/latest/getting-started/login)を参照してください。

### Docker アクセスは明示的な選択

Docker デーモンソケットの制御権は root 権限に近いため、導入時にサービスアカウントをそのグループへ自動追加することは**ありません**。[Docker マネージャー](/docs/ja-JP/latest/apps/docker)にローカルエンジンを管理させたい場合は、システムモードの導入時に `--docker-access` を明示的に付けます。

```bash
sudo deployment/bootstrap/install-relaxkonos.sh --mode system --bundle /path/to/release --docker-access
```

- この選択は root のみが読めるポリシーファイルへ書き込まれます。Docker が導入済みなら、インストーラーがアクセスを付与してサーバーを再起動します。
- Docker を RelaxKonOS が後から導入した場合、ヘルパーが導入後に同じ固定の認可を行い、そのタスクを「再起動が必要」と記録します。サーバーを再起動してから Docker の状態を更新してください。
- **このオプションがない場合、Docker の導入はホストを変更する前に実行を拒否します**。半分だけ変更してから失敗することはありません。
- ユーザーモードのホスト管理制限はサーバーで強制し、ソケット権限や一度の確認では迂回できません。

### ヘルパーが利用できない場合

ヘルパーが存在しない、削除された、または呼び出しを拒否した場合、該当する機能は理由を示す安定した問題コードで失敗します。たとえば昇格を要するプロキシーや Docker の操作は完了できません。このとき**稼働中のワークロードは中断されず**、保存済みの設定もロールバックされません。失敗がホストへ触れる前だったか後だったかは記録されるため、原因を修正して再試行できます。

## ソースからサーバーを起動する

```bash
cd RelaxKonOS.Server
dotnet run
```

本番環境では `appsettings.json` の `Jwt:Secret` を 32 文字以上のランダム文字列に変更し、リバースプロキシで HTTPS を終端してください。

## クライアントの起動

```bash
cd Client/RelaxKonOS.Client.Desktop
dotnet run
```

ログインウィンドウが開きます。**ホスト OS** のアカウント資格情報でサインインします。

ログイン画面では **SSH** も選べるため、RelaxKonOS Server を実行していないホストへ先に接続できます。SSH モードはホスト鍵を確認し、保守向けの専用デスクトップを提供しますが、RelaxKonOS ワークスペースは作成しません。導入や保守に使う前に[サーバーセンター](/docs/ja-JP/latest/apps/server-center)を読んでください。

## 初回サインイン

1. クライアントを起動してログインウィンドウを待つ
2. サーバーマシンのホスト OS 資格情報を入力
3. デスクトップが開き、ワークスペースが作成・同期されます

> システム認証はホストが検証し、Alias は独立したパスワードハッシュを同じホストユーザーに結び付けます。サーバーはシステム認証パスワードを永続保存せず、資格情報の記憶は端末内安全保存の明示的選択です。
