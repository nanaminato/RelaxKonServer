# リモート導入の手順

未導入のリモートホストへ、デスクトップのサーバーセンターから RelaxKonOS Server を導入する手順です。Android は配置が異なりますが、入手元、モード、操作結果、正常性確認の原則は共通です。Windows 10/11 本機は[本機管理](/docs/ja-JP/latest/getting-started/windows)を使い、SSH は不要です。

## 1. ホストと認証情報の準備

1. [ダウンロード](/downloads)から端末に合うクライアントを取得し、対象アドレス、SSH ポート、管理アカウント、パスワードまたは秘密鍵を確認します。
2. 対象で SSH を有効にし、端末から接続可能か確認します。初回導入に既存 Server API は不要です。
3. ホストのコンソールまたは信頼する管理者から SSH 鍵の指紋を取得します。変化した場合は再導入、鍵更新、アドレス変更などの理由を確認します。
4. 対象アーキテクチャ、空き容量とユーザークォータ、Server ポートを確認します。既定は 5000 で、使用中なら別のポートを選びます。

| モード | 必要条件 | 選択する場合 |
| --- | --- | --- |
| Linux システム | 対応 Linux、systemd、Python 3、root または sudo | システムサービス、複数ユーザー、明示的なホスト管理権限が必要 |
| Linux ユーザー | 非 root、Bash、Python 3、curl、unzip、realpath、stat、find、sha256sum、flock | sudo や systemd なしで現在のユーザー専用に導入 |
| Windows システム | システム PowerShell、昇格済み管理者 SSH セッション | Windows 10/11 または Windows Server のサービスをリモート管理 |

Linux システムの既定対象は Debian 12 と Ubuntu 22.04/24.04/26.04 です。他の環境は詳細設定で許可し、依存関係・権限の検査も必要です。Windows 個人モードは対象 PC の本機入口から導入し、この SSH 手順では選択しません。

## 2. SSH ホストの追加と信頼確認

1. サーバーセンター／サーバーの導入・管理を開きます。デスクトップのログイン画面から SSH に進むこともできます。
2. アドレス、SSH ポート、アカウントを入力し、対応するパスワードまたは秘密鍵方式を選びます。必要なら鍵のパスフレーズも入力します。
3. 指紋を照合し、対象ホストと確認してから信頼して接続します。鍵変更時に検証を省略しないでください。
4. 接続を保存する際は認証情報の保存選択を確認します。秘密は端末の安全な領域に保存し、ワークスペース同期しません。

## 3. 事前検査とモード選択

ホストを選んで環境検査を実行し、OS、アーキテクチャ、権限、依存関係、導入状態、ポートを確認します。失敗した項目を先に解決します。Linux システムは一般 SSH アカウントと sudo を使え、sudo パスワード空欄では現在の SSH パスワードを試します。Windows システムは昇格済み SSH が必要で、Linux ユーザーモードは root を拒否します。

既存環境がある場合は識別子、モード、ディレクトリを照合し、[保守手順](/docs/ja-JP/latest/apps/server-maintenance)に従います。別の環境を初回導入として上書きしないでください。

![スクリーンショットの仮画像：撮影箇所：事前検査とモード選択。OS、アーキテクチャ、権限、依存関係、既存の導入状態を示します。](/assets/docs/screenshots/ja-JP/remote-preflight.svg)

## 4. パッケージの入手元

| 入手元 | 指定する内容 | 転送場所 |
| --- | --- | --- |
| 公式安定版 | 公式入手元、任意の HTTPS カタログ | ホストがダウンロードし、公式 ZIP 摘要とファイル一覧を検証 |
| ローカル ZIP | 端末の ZIP を選択 | クライアントがアップロード。対象がインターネットへ接続できない場合にも利用 |
| サーバー上の ZIP | 対象ホストの ZIP 絶対パス | 対象が直接読み込み、クライアントから転送しません |
| カスタム HTTPS | ZIP HTTPS URL と完全な SHA-256 | ホストがダウンロードし、指定した摘要で検証 |

Windows/Linux システムには `*-server.zip`、Linux ユーザーには `*-user-server.zip` を使います。`*-client.zip` では Server を導入できません。すべての入手元で種類・アーキテクチャを検査し、ローカル ZIP も必須ファイル、安全な展開、マニフェスト構造を検証します。公開版はカタログで確認し、ソース説明だけで過去のパッケージの機能を判断しません。

![スクリーンショットの仮画像：撮影箇所：4 種類の入手元と選択パッケージ。種類、版、アーキテクチャを残し、認証情報付き URL を隠します。](/assets/docs/screenshots/ja-JP/remote-source.svg)

## 5. ディレクトリ、ネットワーク、TLS、権限

1. 対象の絶対パスでプログラム・データディレクトリとポートを設定します。Linux ユーザーは XDG 設定・状態・キャッシュも指定でき、重複を避けます。
2. 本機だけならループバック、他の端末からなら LAN と実際の IP／ホスト名に合う HTTPS 証明書を選びます。LAN 待ち受けだけでファイアウォールは開きません。
3. システムモードは証明書なし、自分の PFX/P12 または PEM チェーンと秘密鍵、自己署名を選べます。証明書パスワードは確認画面に表示しません。
4. 必要なパスだけを許可します。Linux 管理者/root の範囲は別途設定します。Docker は既定で無効で、必要なら明示的に許可します。
5. Linux ユーザーは既定でループバックを使い、クライアント管理の SSH トンネルで接続できます。[ユーザーモード](/docs/ja-JP/latest/getting-started/user-mode)の制限も確認します。

![スクリーンショットの仮画像：撮影箇所：ポート、ディレクトリ、待ち受け、TLS、ファイル権限。証明書パスワードを隠します。](/assets/docs/screenshots/ja-JP/remote-options.svg)

## 6. 確認、実行、結果の検証

送信前にホスト、モード、入手元、ディレクトリ、ポートを再確認します。同じ環境では 1 回の操作だけを進め、別のクライアントから重複送信しません。転送、実行、結果確認の順に観察します。総量が不明な転送では割合を表示しない場合があります。

![スクリーンショットの仮画像：撮影箇所：最終確認。対象ホスト、モード、入手元、ディレクトリ、ポートの要約を示します。](/assets/docs/screenshots/ja-JP/remote-review.svg)

転送 100% は導入完了ではありません。ホストの成功結果、導入状態、独立した正常性確認が必要です。操作 ID を控え、失敗時は段階、問題コード、ログを確認します。画面終了や起動スクリプトの終了コードだけでは判断しません。

![スクリーンショットの仮画像：撮影箇所：導入結果と正常性確認。操作 ID、段階、結果記録、導入状態、正常性を示します。](/assets/docs/screenshots/ja-JP/remote-result.svg)

## 7. 導入後の接続

Server ログインに戻り、設定した到達可能アドレスと対応するシステムアカウントまたは Alias を使います。ループバック限定や Linux ユーザーは SSH トンネルを利用でき、SSH ホスト上の `http://127.0.0.1:5000` など実際のポートを指定します。HTTPS の名前と信頼チェーンは引き続き検証します。SSH デスクトップ自体は Server ワークスペースではありません。

## 失敗時の確認順序

| 現象 | 次の確認 |
| --- | --- |
| SSH 失敗・指紋変更 | アドレス、SSH ポート、アカウント、鍵を確認し、ホストを特定してから再試行 |
| sudo／管理者検査失敗 | 対象モードの権限を満たすか確認し、日常 Server の高権限化で回避しない |
| 種類・アーキテクチャ・摘要不一致 | ZIP 入手元、RID、モード、摘要を照合し、公式検証を無効にしない |
| 容量・クォータ不足 | 一時配置のボリュームとアカウントクォータを確認し、確保後に再検査 |
| 中断・結果不明 | 同じホストに再接続し、状態と元の結果を確認してから新操作を送信 |
| 導入済みだが接続不可 | 待ち受け、ポート、ファイアウォール、TLS、接続先を確認してから再導入を判断 |
