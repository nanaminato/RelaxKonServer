# セキュリティモデル

> 現在のソース機能を説明します。公開パッケージの内容は[リリースノート](/releases/0.1.2)、検証状況は関連する実装文書を参照してください。

ホスト OS の ID と実行権限が基準ですが、システム認証と Alias は別の資格情報入口です。Windows は LogonUser、Linux は PAM/NSS を使用します。Alias は独立した一方向パスワードハッシュを既存のホストユーザーと Workspace に結び付けます。サーバーはシステム認証パスワードを永続保存しません。利用者が明示的に記憶する端末内資格情報は OS 安全ストレージまたは Android 保管庫で管理します。

## ファイルとアプリの認可

Windows 10/11 個人モードの所有者は導入を開始したユーザーの SID に結び付きます。所有者はその環境の RelaxKonOS 管理者機能を持ちますが、Server は非昇格で動作します。導入・保守で UAC を使って独立した LocalSystem ヘルパーを設定し、別の管理者の承認でも所有者は変わりません。

ファイル昇格は確認済み範囲に制限され、明示的な管理者ターミナルは所有者とペアリング端末に LocalSystem コマンド実行を許可します。本機認証は所有者だけが行い、秘密鍵は端末内に保持します。端末失効でトークンと Hub 接続は無効になります。個人モードはユーザーをまたぐ Guardian を提供せず、Windows Server では利用できません。

[Windows 10/11](/docs/ja-JP/latest/getting-started/windows)を参照してください。

通常のファイル操作は結び付いたホスト ID・パス・OS 権限に従います。アプリ権限は OS 権限の代わりになりません。保護ディレクトリは別のファイル認可と狭い Helper 契約を使用します。閲覧拒否は空ではなくアクセス不可と表示します。Linux ユーザーモードは現在の Unix home に限定し、ファイル昇格を提供しません。

## 管理者認可と Helper

システムモードのシステム認証済み管理者/root は資格を動的に確認し、条件を満たす非ファイル操作ではパスワード再入力を省きます。一般ユーザーと Alias は選択した有効な管理者を明示的に認証し、対象が限定された短期間・トークン連動の認可を得ます。別アカウントの Guardian/スクリプト操作は今回の明示的承認が必要です。ファイル操作は別のパス認可に従います。

Server は最小権限で動作し、Helper は固定・強い型・監査付きの操作だけを受け付けます。導入権限、サービスアカウントによる Helper 呼び出し、現在の利用者による対象管理は別の条件です。Docker socket アクセスはシステム導入時の明示的な選択です。Linux ユーザーモードは Docker・ファイアウォール・プロキシ・証明書などのホスト管理を無効にします。Helper 不在や拒否時はエラーを示し、高権限 Server に切り替えて迂回しません。

## 資格情報と診断

パスワード・秘密鍵・トークンをログ・監査・診断に記録してはいけません。Alias ハッシュと可逆の秘密は別物で、長期保存するアプリ秘密には制御された暗号化を使います。端末内保管庫と SSH 資格情報は Workspace 同期の対象ではありません。資格情報の変更や削除で既存セッションが失効する場合があります。

HTTPS・入力検証・パス正規化・認可・監査が操作を制限します。アップロード・破壊的操作・復元にはそれぞれの確認範囲があります。個人モードの明示的な管理者ターミナルは上記の LocalSystem 実行権限を持つため、通常のユーザーターミナルとは権限が異なります。
