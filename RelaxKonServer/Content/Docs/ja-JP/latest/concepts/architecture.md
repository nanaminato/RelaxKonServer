# クライアント / サーバー アーキテクチャ

RelaxKonOS はピクセルストリーミングではなく**状態同期**モデルに従います。

## 責務の分担

### クライアント

- デスクトップシェル、タスクバー、スタートメニュー
- ウィンドウマネージャーとモーダルダイアログ
- アプリ UI とローカル描画
- 入力処理とキーボードルーティング

### サーバー

- ID とサインイン
- ワークスペースのライフサイクルとデバイス
- ストレージと同期
- リモートランタイムとリモートサービス
- プラットフォームサービス（Docker、ファイアウォール、証明書、Web サーバー、Git、トンネル、プロキシーなど）

> サーバーは**デスクトップ画像をキャプチャまたは生成しません**。

## 典型的なやり取り

```text
1. ユーザーがクライアント側のウィンドウで入力
2. クライアントが「意図」をプロトコルメッセージに符号化
3. サーバーがホスト OS 上で操作を実行
4. サーバーが構造化された結果を返す
5. クライアントがネイティブコントロールで描画
```

## ピクセルストリーミングではない理由

| 観点 | ピクセルストリーミング | 状態同期 |
| --- | --- | --- |
| 転送内容 | 画像フレーム | 状態と意図 |
| 文字の品質 | 解像度に依存 | ネイティブで常に鮮明 |
| 操作の遅延 | 符号化と転送を含む | ローカルで処理 |
| 帯域 | 画面変化に比例 | 操作量に比例 |
