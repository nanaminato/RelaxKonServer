# サーバーモジュール

RelaxKonOS のサーバーは 1 つの巨大なプログラムではありません。Core が起動、認証、ワークスペース、基本ストレージ、プロトコル、復元を担い、それ以外のサーバー機能は**モジュール**として登録されます。モジュールは必要なときに有効化でき、アイドル時にはメモリを解放できます。クライアントが見るのは「このサーバーが今できること」だけで、モジュールの読み込み方法ではありません。

## モジュール・コンポーネント・アプリ

| 対象 | 内容 | 管理場所 | モジュールを有効化すると一緒に導入されるか |
| --- | --- | --- | --- |
| サーバーモジュール | ターミナル、Git、Docker 管理など RelaxKonOS 自身のサーバー機能単位 | コンポーネントセンター → サーバーモジュール | — |
| コンポーネント | Nginx、Mihomo、Docker Engine、FRP などのホストソフトウェア | [コンポーネントセンター](/docs/ja-JP/latest/apps/component-center) | いいえ |
| アプリ | クライアント上のウィンドウと UI（ターミナル、ファイルマネージャー、Docker 画面など） | 各アプリ | いいえ |

境界は一方向です。Docker モジュールを有効化しても Docker Engine は導入されず、モジュールを無効化・休眠しても、導入済みの Docker を停止したり、コンテナを削除したり、業務設定やユーザーデータを消したりしません。ソフトウェアの導入・更新・削除は常にコンポーネントの管理フローを通ります。モジュールが有効でもソフトウェアが無い場合は、入口を示してコンポーネントセンターへ案内すべきで、「モジュールが有効」を「機能が使える」と扱ってはいけません。

## 公式モジュール

現在 Host にコンパイルされている公式モジュールは 9 個です。設定名はモジュール ID から導出され、`relaxkonos.system-performance` は `Modules:SystemPerformance` になります。

| モジュール | モジュール ID | 設定名 |
| --- | --- | --- |
| ターミナル | `relaxkonos.terminal` | `Terminal` |
| ファイアウォール | `relaxkonos.firewall` | `Firewall` |
| システムパフォーマンス | `relaxkonos.system-performance` | `SystemPerformance` |
| Git | `relaxkonos.git` | `Git` |
| Tailscale | `relaxkonos.tailscale` | `Tailscale` |
| Docker | `relaxkonos.docker` | `Docker` |
| 証明書 | `relaxkonos.certificates` | `Certificates` |
| Web サーバー | `relaxkonos.webserver` | `Webserver` |
| プロキシ | `relaxkonos.proxy` | `Proxy` |

Core は常に残ります。起動、認証、ホストモード、認可、基本ストレージ、ワークスペース、プロトコル、Helper チャネル、復元の入口は無効化できるモジュールには含まれません。

## 有効化と反映

- スイッチは設定 `Modules:<設定名>:Enabled`（例：`Modules:Git:Enabled=false`）です。**再起動で反映**され、実行中プロセスのモジュール集合は起動時に固定されます。
- `Modules` 設定がまったく無い場合は全モジュールが有効で、モジュール化以前の挙動と一致します。未知のモジュール名、真偽値でない値、未知の設定は集合を黙って変えず、起動を失敗させます。
- サインイン後は読み取り専用の一覧 `GET /api/v1.0/server/modules` を取得できます。各モジュールの有効状態、依存、無効化の阻止理由、駐留状態を返します。**状態の取得でモジュールが起動することはありません。**
- 無効化の前には依存と逆依存を確認します。有効な他モジュールが依存している場合や、未完了の処理・復元責務が残る場合は、暗黙に連鎖無効化せず阻止理由を示します。

## 駐留とオンデマンド読み込み

モジュールの「アンロード」は**メモリからの解放**だけを意味します。ファイル削除、設定変更、業務データの変更、外部サービスの停止は行いません。

| ポリシー | 動作 |
| --- | --- |
| 常時読み込み | 最初の読み込み後は常駐 |
| アイドル時に遅延解放（既定） | 最後のリースが終わってから猶予期間（既定 300 秒）を待つ |
| サインアウト後に解放を試行 | セッション終了直後にそのセッションが使ったモジュールを確認し、他者が使用中なら最後のリースまで待つ |

- 起動（ウェイク）は実際の業務リクエストで発生します。認証、認可、有効状態、プラットフォームの確認が**先に通り**、その後にモジュールリースを取得します。未認証・権限なしのリクエストは読み込みを起こさず、通常のリクエストがモジュールをダウンロードしたり、有効化したり、ソフトウェアを導入したりすることもありません。
- 同じモジュールへの同時初回アクセスは 1 回の読み込みにまとめられます。ウェイクには 30 秒の制限と待ち行列の上限があり、タイムアウトや過負荷では安定した一時利用不可エラーを返し、副作用のあるリクエストを再実行しません。
- 現時点で解放可能なオブジェクトグラフを宣言しているのは Git、ファイアウォール、Tailscale で、解放レベルは「オブジェクト / キャッシュ / 接続」です。アセンブリのアンロードと別プロセス終了は未提供のため、ワーキングセットが即座に減るとは約束しません。
- 読み込み失敗は安定した理由（`module-load-failed`、`module-wake-timeout`、`module-wake-overloaded`、`module-host-stopping`）として残ります。UI は理由と再試行の入口を示し、失敗を成功として表示しません。

## 管理する場所

- **デスクトップクライアント**：コンポーネントセンター → サーバーモジュールで、一覧、依存、駐留状態、ヘルスチェックを確認できます。有効化・無効化・ウェイク・休眠の試行・駐留ポリシーの変更はいずれもプレビュー計画を経てから送信され、モジュールパッケージのアップロード導入もデスクトップ側で行います。
- **Android**：同じ入口から一覧を確認し、同じ計画ベースの操作を送信できます。モジュールパッケージのアップロードはありません。
- **設定 → システム**は読み取り専用の要約とコンポーネントセンターへのリンクだけを残します。

## 現在の状態とリリースの扱い

- モジュールカタログと有効化スイッチは 2026-10-28 にソースへ入りました。公開済みの 0.2.0-v1a（2026-10-04）はこの作業より**前**なので、ここで説明した一覧と駐留状態はモジュール化を含むビルドへ更新してから現れます。
