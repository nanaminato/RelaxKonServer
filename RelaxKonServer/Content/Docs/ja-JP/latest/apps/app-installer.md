# アプリインストーラー

アプリインストーラー（App Installer）は RelaxKonOS のアプリケーションパッケージを導入・更新します。外部アプリを組み込みアプリと同じランタイム、ウィンドウ管理、権限モデルへ引き入れつつ、**利用者による確認の段階を残します**。

## 概要

アプリケーションパッケージは、マニフェストとアセンブリを含むアーカイブで、独自の言語リソースやアイコンを同梱することもあります。インストーラーは安全に展開し、バージョン付きディレクトリへ導入し、共有のパッケージカタログへ登録します。その後、シェルがそのアプリを検出します。

## 利用が適する場面

- 自作アプリの配布：開発者 CLI でアプリケーションパッケージにまとめ、インストーラーへ渡します。
- 外付けのデスクトップシェルを導入し、既定のデスクトップ表示を変える（RelaxKonOS のメインウィンドウ内でのみ動作し、**ホスト OS のデスクトップを置き換えることはできません**）。
- ファイルマネージャーからパッケージを直接開き、インストーラーに処理させる。

## 現在の機能

- このマシンで選んだパッケージからの導入、またはサーバーファイルシステムからの選択（確認できるよう先にローカルへステージングします）。
- 導入と更新：同じアプリの新バージョンは、上書きではなくバージョン付きディレクトリへ導入します。
- ファイルマネージャー連携：パッケージをダブルクリックすると「アプリで開く」としてインストーラーへ渡します。
- パッケージは独自のローカライズファイルを同梱し、ワークスペースの言語に追従します。
- パッケージカタログがアプリ検出の唯一の情報源で、インストーラーが維持します。

## 権限とセキュリティ

- **`v2` のパッケージは署名も sandbox もありません。** インストーラーは安全な展開と登録のみを行い、**パッケージの出所を検証したり、できることを制限したりしません**。信頼できるパッケージ、または自分でビルドしたパッケージだけを導入してください。
- マニフェストは権限モデルのバージョンとパッケージ種別を宣言します。欠落または非互換のパッケージは有効化されません。
- アーカイブの展開には上限があり、範囲外のパスやその他の安全でない項目を拒否します。
- アプリはシェルが提供するコンテキストを通じて操作を要求し、サービスコンテナー、認証セッション、リモートファイル API へ直接アクセスしません。

## プラットフォーム差

インストーラーとパッケージ形式は Windows と Linux で同一です。差異はアプリ自身がホスト能力をどう使うかに現れます。

## 既知の制限

- **導入済みは信頼済みではありません**：署名も sandbox もないため、パッケージの導入は作者を信頼することと同じ意味です。画面は「導入済み」を「確認済み」として提示しません。
- デスクトップシェルのパッケージは、利用者が個人用設定ページで明示的に選択した後にのみ読み込まれます。非互換または初期化失敗の場合は現在のデスクトップを使い続けられ、既定のデスクトップへフォールバックし、ワークスペース内の選択意図は上書きされません。
- パッケージの欠落、非互換、無効化、初期化タイムアウトでデスクトップが使えなくなることはありません。
