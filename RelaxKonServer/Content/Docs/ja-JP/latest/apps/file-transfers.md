# ファイルアップロードと再開

> このページは現在のソース機能を説明し、特定パッケージの収録機能一覧ではありません。公開成果物と日付は[リリースノート](/releases/0.1.2)、検証状況はリンク先の実装記録で確認してください。

## アップロード・再開・中止

デスクトップと Android の大容量アップロードは、全ファイルをメモリに置かず分割セッションを使います。転送バイト・進捗・速度・中止を表示し、小さいファイルは明示的な上限を持つ単一要求を使用できます。

1. リモート保存先と端末内の元ファイルを選び、競合処理を確認します。
2. サーバーがセッションを作り、チャンクサイズと確認済みオフセットを返します。
3. 中断後はサーバーのオフセットを照会してから再開します。端末内の進捗だけでは成功を判断できません。有効なセッションと変更されていない利用可能な元ファイルが必要です。
4. 全バイト受信後に別途確定します。同一ボリューム内の原子的な改名で一時ファイルを保存先に反映します。100% の表示だけでは確定成功になりません。
5. 中止でセッションを破棄し一時ファイルを清掃します。期限切れや無効化時は表示に従って再開始します。

## パス・権限・容量

読めないディレクトリを空として表示しません。保護された保存先には個別のファイル認可と制限された Helper 経路を使用し、ホスト権限を迂回しません。認可期限が切れたら再確認し、ユーザーモードは現在の Unix home に限定します。宣言サイズ・空き容量・一時領域予算をサーバーが検証するため、再開対応はサイズや保存期間が無制限という意味ではありません。

## Android と検証

Android はランダムアクセスできない選択文書を再開可能な元データとして一時保存し、アプリ単位の転送とフォアグラウンド通知で追跡します。プロセス終了・バックグラウンド制限・元データ権限失効・実ネットワーク切替は個別に検証し、どのバックグラウンド条件でも完了するとは約束しません。

ダウンロードはディスクへストリーム保存します。分割セッションはアップロードの説明で、ダウンロードが同じプロトコルを使うことを意味しません。SSH 転送は Server API ではなく SFTP を使用します。
