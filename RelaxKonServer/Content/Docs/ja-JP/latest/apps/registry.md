# 構成レジストリ

構成レジストリ（Registry）は、**サーバーのスキーマが明示的に許可した構成上の希望状態**とその同期状態を閲覧する組み込みアプリです。

**ホスト OS のレジストリではありません。** ホストの Windows レジストリ、任意のデータベース表、機密、セッション、高リスクなコマンドへの入口は提供せず、パスはコード内のスキーマ許可リストで制御されます。

## 概要

画面は左にキーツリー、右に値テーブル、下にエディターを配置します。利用者は自分のスコープ内の論理レジストリ値を新規作成、変更、削除でき、更新するとサーバーから再読み取りします。

同期、バージョン、再起動は内部実装であり、利用者には表示しません。

## 利用が適する場面

- ワークスペース単位の構成項目を、ファイルを直接編集するのではなくユーザーごとに確認したい。
- 任意の設定テキストを露出させず、スキーマで制約された単一の構成入口がほしい。

## 現在の機能

- キー単位の閲覧：クライアントは現在開いているキーの**直接の子キーと直接の値**のみを要求し、ルートキーを展開したときに全体を取得することはありません。
- 編集：自分のスコープ内の値の新規作成、変更、削除。
- 永続化：サーバーのメモリ内レジストリが現在の状態を保持し、変更は短い同期待ちの後にまとめてデータベースへ書き戻し、正常終了時にもう一度フラッシュします。
- 既定項目：ワークスペースのターミナル外観、デスクトップ設定、ブラウザー設定、ウィンドウレイアウトは、それぞれのキーの既定値として直接レジストリへ書き込まれます。旧構成ファイルは読み取り、移行、書き戻しのいずれにも関与しません。

## 権限とセキュリティ

- 読み取りは認証済みユーザー識別子をテナント境界とします。未認証、未知のスコープ、他ユーザーのデータには到達できません。
- 利用者が作成・削除できるのはワークスペース配下のキーのみです。キーを削除すると子キーと値もまとめて削除されます。
- キーと値は同じ所有権境界で分離されるため、二人の利用者の一覧が互いのデータを含むことはありません。
- 本アプリはオペレーティングシステムのレジストリへアクセスしません。

## プラットフォーム差

本アプリと API は Windows と Ubuntu で**同一のマネージド実装**を共有するため、プラットフォーム分岐はありません。

## 既知の制限

- 同期、バージョン、再起動の状態は表示しません。これらは内部実装です。
- 編集履歴、楽観的同時実行、複数インスタンス間のキャッシュ無効化は未提供で、後続段階です。
- 汎用の構成パネルとして扱わないでください。スキーマ許可リスト外のパスには到達できず、画面が存在することによって開放されることもありません。
