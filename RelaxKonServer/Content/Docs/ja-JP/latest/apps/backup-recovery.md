# バックアップと復元

> このページは現在のソース機能を説明し、特定パッケージの収録機能一覧ではありません。公開成果物と日付は[リリースノート](/releases/0.1.2)、検証状況はリンク先の実装記録で確認してください。

## 異なる三つの操作

| 操作 | 現在の範囲 |
| --- | --- |
| アプリ改訂のロールバック | 古いイメージ・設定を利用し、ボリュームや DB のデータ移行を取り消しません |
| 定義のバックアップと復元 | サーバーに暗号化定義アーカイブ・マニフェスト検証・読み取り専用事前確認・新しい停止インスタンスへの復元経路があります |
| ボリューム/DB 復元 | 整合性アダプターと実検証が未完了で、復元可能とは紹介できません |

## 定義の復元

1. 定義バックアップを作り、再読み取り・認証タグ・ダイジェストの検証を待ちます。Verified のマニフェストだけが復元に進めます。
2. バックアップ・鍵・元/先のインストール・オブジェクト版・リソース競合を事前確認します。阻止条件があれば送信できません。
3. 明示的に確認し、新しい停止状態の定義を作ります。古いホストポートやサイト紐付けは引き継がず、既存インスタンス・ボリューム・秘密を上書きしません。
4. 設定を確認し、利用可能な秘密とリソースを別途整えた後、起動やトラフィック切替を確認します。

Android はバックアップ作成・マニフェスト・読み取り専用事前確認まで接続済みで、復元送信 UI は未接続です。復元可能な鍵領域を明示的に設定する必要があります。secrets.json や暗号化オブジェクトのコピーだけで別インストールの復号は保証されません。中断した書き込みは自動再実行しません。

参考：[共通復元契約](https://github.com/nanaminato/RelaxKonOS/blob/master/docs/applications/RelaxKonOS.BackupRecovery.Contract.md)、[Android 復元範囲](https://github.com/nanaminato/RelaxKonOS/blob/master/Client/RelaxKonOS.Client.Android/docs/features/OperationsRecovery.md)。
