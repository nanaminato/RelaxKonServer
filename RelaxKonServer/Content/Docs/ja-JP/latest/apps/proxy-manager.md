# プロキシーマネージャー

プロキシーマネージャー（Proxy Manager）は、RelaxKonOS が管理する**現在のホスト**上でプロキシーコアの導入、設定、起動、停止、監視、更新を行います。

最初に正式対応するエンジンは **Mihomo** です。モジュールはエンジン抽象を中心に構成されているため、後から他のヘッドレスなプロキシーコアを追加できます。特定エンジン専用のマネージャーとしては実装しません。

## 概要

クライアントはプロキシーコアの制御インターフェースへ**直接接続しません**。すべての呼び出しは RelaxKonOS サーバーを経由し、制御インターフェースは既定でローカルホストのみを待ち受けます。制御用シークレットはサーバーに留まり、クライアントへ返されることはありません。

## 動作モード

| モード | 説明 |
| --- | --- |
| TUN | **主要モード。** システムレベルでトラフィックを引き受け、サーバー用途の主形態です |
| リスナーのみ | 待ち受けポートのみを提供し、利用側がそこへ向けます |
| RelaxKonOS のみ | 対象を限定するモードで、後続段階です |

TUN を「高度な任意スイッチ」と扱うのは、本モジュールが意図的に避けているデスクトップ GUI の発想です。

## 利用が適する場面

- サーバー全体の外向きプロキシーが必要で、特定プログラムの環境変数では足りない。
- プロキシーが使えなくなっても管理接続を維持し、自分自身を締め出したくない。
- サブスクリプション、設定、実行時バージョンを一箇所で管理し、戻せる経路を確保したい。

## 現在の機能

- ランタイム管理：導入、更新、ロールバック、削除、整合性検証。管理対象ランタイムと外部ランタイムの両方に対応します。
- 設定とプロファイル：生の設定と管理対象オーバーレイを分離し、複雑な設定を無理に構造化しません。
- サブスクリプション：更新前に検証とバックアップを行い、失敗時はロールバックし、元の URL をそのまま返しません。
- プロキシーグループとノード：グループの表示と選択ノードの切り替え。
- 接続：アクティブな接続の表示と切断。
- DNS：設定テキストに埋め込まず、独立した状態として表示します。
- リアルタイムログ：共通の配信チャネルを再利用し、別系統のプッシュ機構を作りません。
- 管理トラフィック保護：TUN 有効化の前に管理経路のスナップショットを取得し、経路変更後も管理接続が到達可能であることを検証します。
- 復旧：ネットワーク変更前に復旧マーカーを書き込み、起動時に未完了の有効化を検出した場合は無視せず復旧評価へ入ります。
- 緊急無効化：TUN を無効化してネットワークを復元する独立操作。エンジンの削除とは異なり、プロファイルは保持されます。

## 権限とセキュリティ

- **二層の権限が同時に成立**してはじめて操作できます。RelaxKonOS 自身の認可と、ホスト OS の特権です。エンジンが高い権限で動いていても、任意の RelaxKonOS ユーザーが制御してよいことにはなりません。
- 特権ヘルパーは**固定の強く型付けされた**特権操作のみを受け付け、汎用のコマンド実行入口を提供しません。
- 日常の起動と停止で昇格を繰り返すべきではありません。導入と認可は初回に完了し、以後の切り替えに承認は不要です。
- 危険な操作（TUN の管理、ランタイムの管理、復旧の実行）はサーバーの認可を必要とします。
- サブスクリプション URL、認証ヘッダー、制御シークレット、プロキシー口令、秘密鍵は通常のログへ入らず、すべてサニタイズを通ります。
- RelaxKonOS はプロキシーコアのためにシステム保護を無効化したり、全体除外を追加したりしません。OS がバイナリを遮断した場合は診断情報を表示するにとどめます。

## プラットフォーム差

| プラットフォーム | ランタイムの常駐方法 | TUN | 自動リダイレクト |
| --- | --- | --- | --- |
| Windows | 常駐する高権限ヘルパーがプロセスを管理。個別のプロキシーサービスは登録しません | 対応 | 非対応 |
| Linux | 独立したシステムサービス | 対応 | 対応 |

画面はサーバーが報告したプラットフォーム能力に従って項目を表示し、クライアント側で OS を判定しません。

## 既知の制限

- 「RelaxKonOS のみ」モードは後続段階で、現在は TUN とリスナーのみが中心です。
- 設定は「生の設定 + 管理対象オーバーレイ」として扱うため、初版ではすべての設定キーのグラフィカル編集は提供しません。
- 対応するホスト環境がないため TUN 関連の一部シナリオはスキップされています。スキップは合格として数えず、プラットフォーム証跡は対象ホストで別途取得する必要があります。
- Windows で TUN を有効化するには高権限ヘルパーが必要です。単なるスイッチではなく、利用できない場合は理由を画面で明示します。
