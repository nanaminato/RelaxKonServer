# Tailscale マネージャー

Tailscale マネージャーが管理するのは**サーバー上の** Tailscale ノードであり、手元の端末の VPN ではありません。クライアントは `tailscaled` に直接接続しません。状態の読み取り、接続制御、設定変更はいずれもサーバーと特権ヘルパーを経由し、返るのは構造化された結果だけです。

## ページ

| ページ | 用途 |
| --- | --- |
| デバイス | 現在のノードの接続状態、アドレス、テイルネットのデバイス一覧 |
| 接続と設定 | 接続・切断、および DNS の受け入れと告知されたルートの受け入れの二つのスイッチ |
| 初回ログイン | サーバー上で公式ログインを開始し、認証ページをこの端末のブラウザへ引き渡します |
| 操作履歴 | ホストとアカウント単位で保持する操作 ID、元の応答の読み取り、照合とクローズ |

## デバイス

このページは読み取り専用です。ホストの CLI の `status --json` を読み、デバイス名、DNS 名、アドレス、オンライン状態を表示します。

テイルネットのデバイス一覧には**ホストネットワークの認可**（リソース `host/tailscale`）が必要です。認可がない場合もローカル状態は表示しますが、一覧は理由とともに非表示になります。完全に見える空の一覧を返すことはしません。

UI の言語を切り替えても、取得済みの状態を描き直すだけで、ホストへ再問い合わせはしません。

## 接続と設定

変更は接続・切断・設定変更の三つだけです。設定モデルは意図的に狭く、「DNS を受け入れる」と「ルートを受け入れる」の二項目に限り、ネイティブ引数、認証キー、独自のコントロールサーバーは受け付けません。

変更は三段階です。

1. ホストの現在の接続状態と設定を読み取ります。読み取るまで操作は選べません。
2. プレビューでホスト、操作、DNS とルートの変更前後の値を示します。
3. 明示的に確認したうえで実行します。

確認画面はリスクをそのまま示します。**この変更は現在のセッションを含むリモートアクセス、DNS、ルートを中断させる可能性があり、自動ロールバックはありません。** 接続にはノードが既にログインしている必要があり、本アプリが代わりにログインすることはありません。

実行は共通のホスト昇格の入口を通り、サーバーが明示的に要求した場合に一度だけ認可を求めて再試行します。操作は `operationId`、操作者、操作、想定リビジョン、設定の組み合わせで重複を判定します。同じ ID で内容が異なれば拒否し、再送では元の応答だけを返します。

## 初回ログイン

初回ログインのページは「ログインを開始」を押した後にだけ計画を作成し、成功、明示的な確認、操作参照の永続保存がそろってから実行します。

- 認証ページは**「公式ログインページを開く」を押したときだけ**、この端末のシステムブラウザへ渡されます。自動で開くことも、クリップボードへコピーすることも、ディスクや操作履歴へ書き込むこともありません。
- ブラウザへの引き渡しは「開くよう要求した」だけであり、利用者の認証完了やデーモンのログイン完了を意味しません。
- ログインのチャレンジは元のホスト、アカウント、**元のログインセッション**に紐づきます。再ログイン後の新しいセッションは古いチャレンジを受け取れませんが、同じアカウントなら元の操作を読み取り照合できます。
- ウィンドウを閉じても待機が止まるだけで、**発行済みのチャレンジは取り消されません**。

ログイン結果は「発行済み」「ネイティブコマンド完了」「デバイス承認待ち」「不明」のいずれかです。承認待ちの場合は管理画面でデバイスを承認し、ここへ戻って状態を更新し、元の操作を照合してください。

## 操作履歴と復旧

操作参照は現在の OS ユーザーのローカルディレクトリに、ホストとアカウントごとに分けて保存します。保存するのは同一性の参照だけで、認証 URL、設定、結果は含みません。

- 応答が失われた場合、操作を**再実行しません**。開き直すとサーバーに保存された元操作の応答を読むだけで、UI は「照合待ち」のまま変更を無効にします。
- 未解決の操作がある間は、新しい接続・切断・設定・ログインが止められ、先に元の応答を読むよう案内します。
- 結果が不明な場合は「復旧状態を照合」へ進みます。二回連続で同じ観測が得られたら、新しい認可と明示的な確認のもとで**クローズ**できます。

クローズの意味は明確です。ホストの**実測された現在の状態**を受け入れ、その操作による変更のブロックを解除します。**再試行もロールバックもせず、元の操作を成功へ書き換えません。** 元の結果は不明のままで、後から健全に見える状態がその事実を上書きすることはありません。

## 導入と削除

導入は本アプリでは行わず、[コンポーネントセンター](/docs/ja-JP/latest/apps/component-center)が担当します。

| プラットフォーム | 入手元 | 内容 |
| --- | --- | --- |
| Linux | 公式署名付き APT リポジトリ | 固定パッケージ `tailscale`、CLI `/usr/bin/tailscale`、サービス `tailscaled.service` |
| Windows | 公式署名付き MSI | `installer` メタデータを凍結し、MSI をアーカイブとして展開しません |

Linux で公式リポジトリを初めて使う際は、入手元と鍵のフィンガープリントを明示的に確認する必要があります。ホストに既にある別の入手元を上書きすることはありません。Windows では特権ヘルパーが公式配布の同一性を独自に解決し、ダイジェスト、WinTrust の発行者、MSI の製品属性を確認してから Windows Installer を実行します。

削除してもログイン情報と設定は保持されます。導入や更新はサービスを再起動し、現在のリモート接続を中断する可能性があります。

ホストに既にある外部の Tailscale は**自動で引き取りません**。コンポーネントセンターは「外部導入」として報告し、管理権は自前の台帳と検証証拠の両方がそろった場合にのみ認めます。

## 権限とセキュリティ

- 状態の読み取りには認証済みセッションが必要です。制御、ログイン、復旧にはさらにホストネットワークのリソース認可と管理者昇格が必要です。
- 特権ヘルパーは固定の動詞のみを受け付け、パス、任意の引数、リビジョン以外の領域フィールドを拒否します。汎用のコマンド実行は提供しません。
- 各コマンドには実行時間と出力上限があり、タイムアウト、上限超過、不正な出力はすべて失敗として扱います。生の JSON や下位の診断情報が IPC を越えることはありません。
- 認証リンクはクリック時に専用の短期チャネルでのみ渡し、状態、ログ、応答、長期キャッシュには残しません。

## プラットフォームと既知の制限

| プラットフォーム | 現状 |
| --- | --- |
| Linux | 観測、制御、初回ログインを実機で確認済み（Ubuntu 26.04、Tailscale 1.104.4） |
| Windows | MSI 導入、バージョン間変更、ドライバー、再起動後の復旧は別途ホストでの受け入れ確認が必要です |

- 対応バージョン範囲は宣言しません。互換性は実機での受け入れで確認するもので、文書から推測するものではありません。
- UI が公開する設定は「DNS を受け入れる」と「ルートを受け入れる」の二つだけです。ログアウト、認証キー、強制再認証、出口ノード、サブネットルートの告知はいずれも本アプリの範囲外です。
- モバイル版は同じ API を使う**制御端末**であり、スマートフォン上で VPN ランタイムを動かしません。UI の規則と端末での確認は別途維持されます。
- CLI の既知の位置は `/usr/bin/tailscale` と `Program Files/Tailscale` のみで、他の配置は本スライスの範囲外です。
