# Git クライアント

Git クライアント（Git Client）は、RelaxKonOS サーバーの**ファイルシステムにすでに存在する Git リポジトリー**を対象とします。画面はクライアント側でローカルに描画し、作業ツリーの状態、コミット履歴、ブランチ一覧の真実の源はサーバーが `git` をリアルタイムに呼び出して取得します。

## 概要

作業ツリーの状態、ブランチ、履歴、差分は**その時点のスナップショット**です。キャッシュもデータベース作成も行いません。

**認証は完全にホストの領域です。** `git` はホスト OS のプロセスとして実行され、ホストのユーザーと権限を再利用します。RelaxKonOS は Git リモートの資格情報を保存・代理・収集しません。push や pull に資格情報が必要な場合はホスト自身の資格情報ヘルパーや SSH エージェントが処理します。資格情報がない場合 `git` は失敗し、画面が理由を示してホスト側での設定へ誘導します。

## 利用が適する場面

- サーバー上の特定ディレクトリが Git 作業ツリーで、その場で状態確認、コミット、pull を行いたい。
- RelaxKonOS に Git 資格情報を一切渡さずにリポジトリーを操作したい。
- pull でマージ競合が発生し、サーバー側で解決したい。

## 現在の機能

| 機能 | 説明 |
| --- | --- |
| リポジトリー選択 | 登録済みリポジトリー一覧、現在の選択、切り替え |
| 作業ツリーの状態 | ステージ済み／未ステージ／未追跡／競合ファイル、現在のブランチ、上流の先行・遅延数 |
| ブランチ | ローカルとリモートの一覧、切り替え、作成、削除 |
| コミット | ステージするファイルを選び、メッセージを入力してコミット |
| 取得 | 現在のブランチのマージまたはリベース。チェックアウトしていないブランチは安全な早送り更新のみ |
| プッシュ | チェックアウトせずに、現在または指定したローカルブランチを指定のリモートとブランチへプッシュ |
| 履歴 | コミット一覧と単一コミットの詳細 |
| 差分 | 作業ツリー、インデックス、指定コミットの単一ファイル差分 |
| 競合解決 | 三面比較、ハンク単位の選択、ファイル単位のステージ、独立した続行／中止 |
| リバート | 指定コミットに対する逆コミットの作成 |

## 権限とセキュリティ

- すべての操作は**ホスト OS のプロセス**として `git` を呼び出すため、範囲外のアクセスはホストが拒否し、別系統のアクセス制御層を追加しません。
- コマンドはシェル文字列に連結せず、構造化された引数として渡します。
- 作業ディレクトリは登録時に記録したリポジトリーパスに固定し、ファイル引数はそのルート配下に限定し、逸脱を禁止します。
- 危険な操作には確認を求めます。未マージブランチの削除、リバート、未コミット変更を上書きする切り替え、リポジトリー登録の解除。
- 登録の解除は**登録レコードのみを削除し、ディスク上のリポジトリーディレクトリは削除しません**。
- 監査は実行者、時刻、リポジトリー、操作、結果を記録し、資格情報は記録しません。

## プラットフォーム差

`git` の挙動は Windows と Linux で同一で、プラットフォーム差は実行ファイルの検出と起動環境のみです。したがってサーバー側は単一の実装です。

## 既知の制限

現在は**第一段階の範囲**です。以下は未提供で、一部の画面入口はプレースホルダーとして用意され、利用できない旨を明示します。

- チェリーピック、対話的リベース、コミットの並べ替え。
- スタッシュ、サブモジュールの深い管理、タグ管理。
- 組み込みの三方マージエディター（競合解決は現在ハンク単位の選択が中心）。
- 複数リモートの完全な管理。
- 強制プッシュとハードリセット。安全のため公開していません。
- バイナリ差分はパッチ本文を返さず、大きなテキスト差分は切り詰めて明示します。
