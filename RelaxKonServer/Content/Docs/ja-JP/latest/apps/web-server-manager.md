# Web サーバーマネージャー

Web サーバーマネージャーは**入口と振り分けの層**です。このホスト上の Web サーバーインスタンスを検出し、プロバイダーごとに処理を振り分けます。Nginx が最初の完全実装プロバイダーです。別のプロバイダーを追加しても呼び出し側は変わりません。

## 概要

RelaxKonOS は自前の Nginx を同梱する設計でも、Nginx の管理パネルになる設計でもありません。位置づけは次のとおりです。**RelaxKonOS はローカルの Web サーバーを検出し、利用者の認可に応じて監視・統合・管理を行います。**

## 二つの管理モード

| モード | 意味 | 境界 |
| --- | --- | --- |
| 統合（Integrated） | 既存の Web サーバーと統合するが所有はしない | RelaxKonOS が作成した設定断片のみを管理。導入・更新・削除は行いません |
| 管理（Managed） | RelaxKonOS が導入して完全に管理 | 導入、更新、起動、停止、設定、サイト、削除 |

検出された未管理の Web サーバーは**候補**にすぎません。RelaxKonOS が自動で設定を変更することはなく、管理者が明示的に確認した後にのみ統合モードへ入ります。

## 利用が適する場面

- サーバーにすでに Nginx があり、既存設定を引き継がずに新しいサイトを管理したい。
- あるドメインに静的フロントエンド、SPA フォールバック、複数のリバースプロキシ経路を設定したい。
- 証明書の発行と配置を分離したい。証明書マネージャーは Nginx の存在を知りません。

## 現在の機能

- 検出：PATH、一般的な導入先、システムサービス、実行中プロセスなど複数の情報源から候補を探します。
- 読み取り専用の状態：バージョン、実行ファイル、メイン設定、設定ディレクトリ。
- 設定トランザクション：生成、バックアップ、一時ファイル書き込み、検証、コミット、リロード、失敗時のロールバック。
- サイトモデル：静的ルートとプロキシー経路は**排他的な種類ではありません**。静的サイトはルートパスのみ、プロキシー専用サイトはサイト全体を覆うルート経路のみ、複合サイトは両方を使えます。
- 証明書の紐付け：証明書マネージャーに既にある証明書をサイトへ紐付けられます。秘密鍵はサーバーローカルに留まります。
- 更新後の自動リロード：証明書の更新成功後、その証明書を参照する RelaxKonOS 管理サイトだけに安全なリロードを一度実行し、サイト設定は変更しません。
- HTTP-01 統合：既存の Web サーバーが 80 番を保持している場合、チャレンジパスを公開するだけにとどめ、RelaxKonOS はポートを奪いません。
- 権限付与：Linux では静的ディレクトリに対する worker の読み取り権限を明示的に付与できます（読み取りと通過のみで、所有者変更や書き込み権限は行いません）。

## 権限とセキュリティ

- これは単一サーバーの管理者向け**管理者モード**機能で、細粒度のユーザー／ワークスペース認可は使いません。インスタンス、サイト、設定スナップショットはホスト全体のリソースです。
- 検出と読み取り専用の状態はプロセスが読める限り動作します。統合、導入、設定書き込み、リロード、起動停止、証明書配置は RelaxKonOS が十分な権限で動作していることを必要とし、不足時は安定した問題コードを返します。
- クライアントは sudo / UAC / サービスアカウントのパスワードを収集せず、要求パラメーターをシェルコマンドへ連結しません。高権限の実行者は本モジュールが定義した構造化操作と許可パスのみを受け付けます。
- 上流アドレスは任意に書き込める URI ではありません。資格情報、制御文字、未知のスキーム、未宣言のポートを拒否し、解決後に再検証することで、サイトのフォームが内部ネットワークの探索口になることを防ぎます。
- 設定トランザクションはインスタンスごとに直列実行されます。外部変更がスナップショットと一致しない場合は中止し、利用者の変更を上書きせず再読み取りを求めます。
- サイト削除やアンインストールは、所有権マーカーがありハッシュが一致するファイルのみを削除し、利用者のディレクトリを再帰的に削除しません。

## プラットフォーム差

- 対象は **Ubuntu 24.04 LTS** と **Windows Server 2016 以降**です。
- Linux ではシステムサービスまたはネイティブコマンドで Nginx を制御し、Windows では RelaxKonOS サービスが管理対象 Nginx のプロセスライフサイクルを担います。

## 既知の制限

- **Nginx 統合は現在の第一段階の範囲**です。導入、更新、削除、設定トランザクションとサイト管理は実装済みで、残りのプロバイダーは未実装です。
- IIS、Apache、Caddy は抽象の境界のみで**実装されていません**。画面は利用可能であると主張しません。
- 発行と自動更新後にトリガーされるリロードは、後の段階でさらに自動化できます。未実装のプロバイダー能力を先に約束することはありません。
- 複合サイト設定、ディレクトリ認可、機密パスの制限は、実装どおりに記載し、先に約束しません。
